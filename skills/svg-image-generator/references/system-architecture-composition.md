# 系统上下文与架构协作构图

用于说明系统负责什么、与谁交换什么，或解释跨系统职责、数据分层与执行过程。参考 [Better Harness 评审架构案例](examples/raven-harness-assessment.md)：它组合了静态分层、产物目录和协作泳道，并非一张纯系统上下文图。

## 先选图的层次

| 读者的问题 | 画什么 | 留在其他视图的内容 |
| --- | --- | --- |
| 系统与谁协作，边界在哪里 | 核心系统、使用者、外部系统、带含义的关系 | 内部模块、函数、完整任务目录 |
| 各部分负责什么，依据什么 | 职责分区、证据或数据分层、依赖 | 每个请求的时间顺序 |
| 一次任务如何完成 | 参与方泳道、触发、请求与返回、关键状态 | 不影响流程理解的内部实现 |
| 最终保存什么、如何追溯 | 产物分组、来源引用、必要的版本／ID | 完整字段表和无关目录 |

先用一句话明确当前视图的阅读目标。需要同时回答两类问题时可并列两个有标题的视图，或另出详图；不靠更多跨区箭头把所有层次混在一起。

## 系统上下文：先画黑盒边界

把本次讨论的系统作为一个对象，用一句职责说明命名；外围放实际使用它的人和与它交换信息的系统。将关系整理成“发起方 → 动作／数据 → 接收方”，再决定位置与走线。

- 围绕核心只表示视觉组织；属于同一产品、部署在同一机器、调用同一接口是不同关系。若需要边界框，标明它表示产品、责任或部署边界。
- 内部插件与被连接的外部系统分开，例如“问题跟踪适配能力”与“外部问题跟踪服务”。不能因集成某软件就把它画进系统内部。
- 箭头标签写“提交评审任务”“查询指标标准”或“返回任务状态”等可理解动作／数据，少用没有解释力的“交互”“数据”。请求与返回都影响读者判断时分别标出方向；仅表示归属时不加调用箭头。
- 同层对象采用相近细节。不要一边是整个外部产品，一边是内部函数、JSON 文件或数据库表；需要讲内部职责时进入独立架构视图。

用户没有要求 C4、部署或网络协议时，不额外套用这些规范或补造技术细节。核心居中、环绕分布也只是可选布局。

## 静态分层与动态流程分开读

静态图回答“谁负责、什么支撑什么”，流程图回答“先后发生什么”。并列展示时，各自保留标题和阅读方向，共享对象保持同名；只有真实跨视图关系才连线，不为表示“这是同一系统”拉一条贯穿全图的箭头。

分层表达应说明层间关系，例如原始事实支撑抽象证据、证据支撑判断。箭头方向按该关系确定，不机械地从上往下画。若金字塔用于表达支撑关系，可采用上窄下宽的梯形，但不能让面积暗示未经测量的数量、价值或性能。

跨系统流程适合按参与方分泳道，时间沿一个方向推进。每个动作放在实际负责的一方；同一参与方的颜色、名称和图标在其他视图中保持一致，颜色仍是辅助识别。

- **触发者与执行者**：用户在编码工具发送 Prompt，可用人的图标和消息气泡表现；后续编排放在 Skill／Agent 泳道。不要将用户发起任务误画成 Web 后台自动启动。
- **请求与返回**：调用方发出请求，服务方返回相应标准、数据或回执。两条线可上下错开并标注内容，避免一个双向箭头掩盖谁先调用。
- **状态与结果**：进度通知与最终结果同步分开；确需用虚线区别时，标签和全图含义保持一致，不把虚线默认解释为异步或可选。
- **获取与固定版本**：来源标准可更新，任务快照固定本次依据；放在它实际发生的步骤，不把“请求标准”和“完成评审”压成同一步。
- **保存与展示**：标清哪一方保存、哪一方查询。如果 Web 经 API 读取结果，不把本地 HTML 画成唯一结果或默认数据源。

不根据模板补造重试、权限、审批或同步语义；已知且影响主线的分支才画入，并让失败落到真正的保留／恢复状态。

## 产物视图用来解释证据链

目录不是时间线。先分清标准快照、原始事实、派生证据、分析结果和可选展示产物，再按内容选择目录或产物集合的画法。需要展示完整目录时，可按语义拆成两列，保留共同根路径并说明是同一目录，避免误读为两套工作区。

只保留能说明关联的标识。例如案例中 `taskId` 关联任务，`groupVersion` 固定判断口径，`indicatorId` 关联标准与结果，`evidenceIds` 指向证据与来源。它们不是可互换的“版本号”，也不是其他系统必须具备的字段。

示例目录、拟议接口、可选预览和未确认命名，要在对应对象附近标明“建议”“暂定”“可选”，并在图的说明中交代方案状态。不要为了画得完整，给未确定的接口编造路由、给目录示意升级为真实协议承诺。

## 布局与核验

完整内容过高时，先考虑分栏、压缩重复的说明和按职责重排，仍过密再拆图。画布改宽不能通过非等比例缩放实现；图标、文字和形状保持比例。角色图标帮助扫读即可，不需要每一步都有装饰。

从用户触发开始走一次任务，核对请求者、接收者、返回内容与先后次序；再从结论反查标准版本、证据和来源。分别核对静态层间关系、泳道责任和产物引用，不用 XML 合法性替代语义核验。

在实际使用尺寸查看 PNG：完整方案图可以作为放大查看的参考，但如果要嵌入正文或幻灯片，必要时另出概览／局部图；增加像素不能让密集文字在缩小后变大。渲染与字体检查见 [渲染参数与排障](rendering-guide.md)。
