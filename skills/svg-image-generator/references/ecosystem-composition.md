# 生态构图

用于产品生态、多组能力归属和已有生态图的调整。[Raven 生态图案例](examples/raven-product-ecosystem.md)展示了一次真实取舍，不是统一画风。系统边界、外部角色和调用关系见 [系统上下文与架构协作构图](system-architecture-composition.md)；多轮反馈的共同处理方法见 [反馈迭代与经验提炼](feedback-iteration.md)。

## 先分清图的语义

在绘制前把内容整理成“核心对象 → 能力分组 → 功能节点”，另记用户、产品形态和外部工具。先回答读者要理解的是“系统负责什么、与谁连接”，还是“产品包含哪些能力、如何扩展”。

- **上下文与边界**：区分系统自己的能力、使用者和外部工具；产品内的插件适配能力与它连接的外部软件不是同一个对象。要画调用或数据流时明确方向与内容。
- **产品生态与归属**：产品形态可围绕共同核心，能力按业务认知分组。连接线可仅表示归属，不必加箭头或暗示调用顺序；外部软件可列入集成能力，但不能据此声称它属于产品部署边界。
- **受众需要简化**：优先删去实现层细节、合并相近类别，保留核心定位与价值。不靠缩小字体把全部原图装进新图。

分组变化时重新核对成员。例如把“AI”和“常用研发工具”合并，可以合并类别而保留所有成员；换用品牌图标不改变功能归属。目标能力、已实现能力和经过验收的能力仍需区分。

## 用布局表达层次

| 读者需要看见 | 可采用的布局 | 常见偏差 |
| --- | --- | --- |
| 一个核心与少量入口 | 共用轨道、短连接或靠近核心的节点 | 入口半径相同，但角度不同，实际间距不等 |
| 少量并列能力组 | 核心周围的分区、四角或横向分组 | 每个分组都画独立中心与圈，削弱整个产品的核心 |
| 同组多个功能 | 围绕组节点的疏密变化、细归属线 | 所有节点均匀排到同一大圈，失去分组语义 |
| 紧凑的单一生态 | 功能贴近所属模块，各组共享整体画布 | 仅扩大画布，把分组拉得像几个互不相干的系统 |

不要求每组都有可见中心、封闭边界或局部轨道。只有用户需要组节点时才画主球；需要自然散布时，使用不同角度与距离，并让成员仍容易归类。可用同一套几何函数，避免全图靠手调坐标累积偏差。

### 等距与聚合

“围绕核心等距”通常同时包含两件事：节点到核心的半径一致、相邻节点的夹角一致。圆上的 n 个入口可用：

```text
angle(i) = start + i × 2π / n
x(i) = centerX + radius × cos(angle(i))
y(i) = centerY + radius × sin(angle(i))
```

三个入口等角时为 120°，任意两点间距为 `√3 × radius`。这是几何方法，不意味着所有生态图必须圆形布局。

用户要求“某组离中心稍远”时，先调整组节点与核心的距离，再整体平移它的功能节点；需要改变组内聚合程度时才单独调整成员。这样不会无意中改变原有疏密与归属。

用户要求“宽一些、矮一些”时，重新排布坐标和标题区域；不要给整图做非等比例缩放。球体、品牌图标、字体宽高比保持不变，再更新 `viewBox` 与导出尺寸。

## 球体、文字和连接线

- 视觉核心应比组节点明显，组节点再区别于功能节点；不要靠把所有标题都放得巨大来强调重点。用户要求加粗时，先提升字重、对比和位置，适度调字号后重新检查空间。
- 圆形图标球容不下长标题时，把图标留在球内，名称与一句短描述放在球下方并居中。半径、标签间隔可复用已有入口的尺度；不要为塞进文字把每个球都扩大。
- 文字也是几何对象：留出标题全宽、描述高度、标签与邻球的空隙。`text-anchor="middle"` 只让文字围绕指定坐标居中，不代表该坐标就是分组中心。
- 品牌图标保留原色与比例；先查当前项目已有素材，或使用用户提供的图。白色图标球上需检查图形的有效面积，外围留白可在不裁伤标志的前提下裁去。没有官方图标的能力使用一致的通用图形，并记录为示意符号。
- 归属线从主球边缘接到功能球边缘，放在图标和文字后面，颜色与线宽弱于节点。可以用遮罩避让文字；不要在线尾添加无语义的箭头。

球心 A 到球心 B，距离为 d、单位方向为 u：线段端点可取 `A + u × (rA + gap)` 与 `B - u × (rB + gap)`。只有 `d > rA + rB + 2 × gap` 时才有可见线段；端点正确也不代表线没有穿过其他标签，仍需渲染检查。

## 将反馈变成有边界的修改

生态图中常见反馈可落到以下具体对象；已确认决策的保留与通用迭代顺序见 [反馈迭代与经验提炼](feedback-iteration.md)。

| 用户反馈 | 应修改的对象 | 顺带核对 |
| --- | --- | --- |
| “合成四个模块” | 类别与成员映射 | 成员不丢失，连接线重新归属 |
| “移到团队协作左下角” | 相对组节点的位置 | 坐标确实左下，标签与连线留白 |
| “像入口球一样大小，改白色” | 半径、表面和前景色 | 图标对比、标题位置，描述不塞进球 |
| “三个入口间距不一样” | 半径和角度参数 | 两两距离、字体宽度与视觉均衡 |
| “替换名称与图标” | 指定节点及其素材引用 | 源图、PNG、标签遮罩与来源说明同步 |
| “迁移所有图” | 指定范围内的图稿与索引 | 目录已移动，旧引用和相对链接仍有效 |

已有图稿的局部修改通常不需要重画整个关系结构。若连续反馈都在纠正同一个结构问题，先调整结构，再做颜色、字重等细节。

## 验收分开进行

1. **语义**：分组、名称、成员与箭头含义符合本轮需求。节点数检查只适用于明确要求保留成员的改图，不把数量当作通用质量标准。
2. **几何**：实际可见球与标签无碰撞；指定等距条件成立；连接到所属对象，端点留在边缘；横版中形状没有拉伸。
3. **呈现**：用现有渲染脚本导出 PNG，并在正常展示尺寸查看。检查中文实际字重、品牌可见性、遮罩误裁、留白与核心是否突出。
4. **交付**：修改 SVG 后更新同名 PNG；目录索引与资源来源指向真实文件。案例源图可内嵌拉丁字体，但中文若仍回退系统字体，就明确这一点；不声称所有机器完全一致。
