# 图形表达与 SVG 绘制

## 先确定图要解释什么

图应让读者看见正文难以一次说清的关系、过程、差异或空间结构。先写出读者看完应理解的一件事，再选择表达方式。无需视觉化的简单比较可以用表格，不为凑配图把文字搬进方框。

| 要解释的内容 | 可考虑的表达 |
| --- | --- |
| 组件职责、边界、依赖 | 关系图、分层图、局部放大 |
| 跨组件交互、任务流转 | 时序图、泳道、分步骤画面 |
| 状态变化、重试、恢复 | 状态图、分支路径、前后状态 |
| 内存、索引、数据结构、算法 | 空间布局、关键中间状态、局部变化 |
| 时间、分布、测量结果 | 有来源和单位的图表 |
| 场景、操作与反应 | 示意插画、操作场景与处理过程组合 |

这些是线索，可以混合或创造更合适的画法。不要把每个问题都画成架构图或同一种卡片布局。

## 事实与阅读顺序

- 先确定抽象层次。不要把“产品”“进程”“函数”“数据”混作同一层的节点而不解释。
- 连线的含义应明确：调用、数据流、依赖和状态转换有不同的语义。箭头落到正确对象，双向关系不要因为排版方便画成单向。
- 用分组、位置、编号或视觉层次组织阅读顺序；颜色服务于有意义的区别，必要时配标签或图例。
- 技术标识保留原名，说明文字贴近正文语言。长说明放在图旁，图内保留理解关系所需的文字。
- 区分真实架构、核实过的过程和假设示意。没有测量依据时不画伪精确比例、性能值、热力分布或排名。

## 可独立渲染的源文件

根元素包含 `xmlns="http://www.w3.org/2000/svg"`、与画布对应的 `viewBox` 和明确宽高。用 `<title>`、`<desc>` 简述主题和读法；可见标题按图片用途决定，不必每张都添加。

下面只展示文件骨架，不是默认构图或画风：

```xml
<svg xmlns="http://www.w3.org/2000/svg"
     width="800" height="320" viewBox="0 0 800 320"
     role="img" aria-labelledby="title desc">
  <title id="title">图片主题</title>
  <desc id="desc">关键关系与阅读方式</desc>
  <defs>
    <!-- 按内容定义 marker、渐变、滤镜或裁剪 -->
  </defs>
  <g font-family="Noto Sans CJK SC, PingFang SC, sans-serif"
     font-size="20" fill="#172033">
    <!-- 在这里绘制实际内容 -->
  </g>
</svg>
```

- **文字**：`<text>` 不会像 HTML 段落自动换行。按语义用 `<tspan>` 或多个文本元素排版，并检查实际字形宽度。文本中的 `&`、`<` 等字符按 XML 转义；程序生成时使用 XML 序列化工具或转义函数。
- **字体**：声明的字体名称不代表运行机器已安装。中文使用覆盖所需字形的字体；通过渲染脚本传入 `.ttf`、`.otf` 或 `.ttc` 文件。脚本的默认字体只负责回退，SVG 中显式设置的字体名称也应与已加载字体匹配。
- **颜色与样式**：独立文件内定义所需样式。不要让外层网页的 CSS 变量、暗色模式或 `currentColor` 的外部赋值决定最终 PNG；需要主题变体时生成对应的具体样式。
- **外部资源**：图片嵌入 `data:image/png;base64,...` 等 data URI。渲染器不执行网页 JavaScript，也不负责下载远程图片或字体。不要用 `<foreignObject>` 承载需要导出的 HTML 文字。
- **图形能力**：渐变、曲线、marker、多子路径、滤镜、裁剪和嵌套变换都可按需使用。绘图技术复杂本身不是缺陷；以目标渲染器的实际输出判断兼容性。
- **边界**：描边、箭头和阴影可能超出几何边界。留出适当画布空间并检查滤镜区域，避免导出后裁切。不要通过扩大整个画布掩盖局部布局问题。

## 从 PNG 反查源文件

用图像查看工具读取真实 PNG，或读取浏览器实际渲染的截图，基于看到的画面判断；不要仅凭 SVG 坐标、文字提取或脚本结果推测视觉效果。在预期嵌入宽度下先看整体，确认表达的关系正确、阅读顺序清楚、重点突出、文字可读，再按需放大排查细节；透明图还要在实际放置的背景上检查。放大像素只能提高导出分辨率，不能解决文字在正文里太小或信息过密。

发现问题回到 SVG 调整文字、布局、连线或滤镜，再导出并重新读取图片确认。每张最终交付图都要经过这个过程，最后一次修改后的文件也不例外。XML 检查只判断语法与根元素，不判断事实、审美、缺字或遮挡；自动测试通过不能证明图片合理。
