# 精选文章深度调研

输入 `input/article.md` 已由审核阶段确定为调研对象。本步骤不重新挑选文章，不修改调研篇数。

读取原文与附加调研要求，生成一篇独立的中文技术文章。以原文支持的机制与证据为基础，将核心问题、实现过程、关键取舍和使用边界讲清楚；用自己的结构组织论述，避免逐段翻译或机械扩写。

- 首段直接交代解决的问题与核心结论。
- 解释实现机制与数据/控制流程；有代码或实验时分析其作用、条件和限制。
- 给出适用与不适用场景，以及读者可以采用的工程建议。
- 区分原文事实、分析推论和建议。没有实际检索时，不声称查阅了其他来源；无数据时不编造基准结果、事故案例或源码结论。
- 结尾保留输入材料中的原文链接。引用原文时克制，正文以分析为主。
- 根据材料决定篇幅与小节，不强制固定字数、对比表、图或虚构生产冲突。材料有限时明确指出，不能用泛泛模板填充。

先基于已有全文完成约 1500～2500 字的完整文章，写入 `output/research.md`，最终回复返回同一 Markdown 正文。不要只输出计划或进度，不写与交付无关的测试文件。

默认不额外联网。仅在任务附加要求明确需要外部核查时，限于 3 个一手来源；完成核查后立即写作，不递归扩大检索范围。已有全文足够解释的机制直接分析，证据缺失的部分标注未知。此阶段应完成一次有边界的技术分析，而非无限探索。

确需图示时，可参考 `references/visual_and_assets_guide.md`，只绘制有依据的关系。将 SVG 写入 `output/assets/`，正文使用 `![说明](./assets/name.svg)` 引用。不强制为每篇文章配图。

所有新增文件都写入 `output/`；不要修改输入材料或调用 GitHub、群通知等交付服务。
