# 测试规划与复现取证

## 从改动和运行反馈动态设计用例

先读 diff 和必要的调用方、路由、持久化与任务处理代码。为每项用户可见改动列出：角色、进入方式、动作、预期结果、影响的相邻功能、后续副作用。关键路径画小型流程图或明确的顺序列表，重点是旅程完整，不要求图形数量。

场景清单按以下问题挑选，而不是机械生成所有组合：

| 改动 | 重点验证 |
| --- | --- |
| 表单/写入 | 合法与非法输入、空值/边界、连续提交、刷新后结果、权限 |
| 列表/查询 | 无数据、分页/筛选、返回与深链接、不同角色的数据边界 |
| 登录/权限 | 未登录、越权、过期会话、多个身份的隔离 |
| 邮件/通知/任务 | 正确接收人/目标、重复处理、链接落点、失败反馈与真实终态 |
| 共享组件/布局 | 使用该组件的关键页面、移动视口、键盘与焦点 |
| 接口/后台逻辑 | 项目已有 CLI/接口测试、存储或队列观察，不能只凭 UI 提示 |

先从改动、需求和用户旅程生成可执行用例，再根据运行反馈迭代：出现新的状态就补分支，发现异常就细化复现条件，观察到关联影响就扩展相邻回归。调整场景、检查点和执行顺序时仍以同一需求为依据，不为消除失败而改变预期。

所有改动文件都需要关联场景，或者明确排除理由。排除是可审查的判断，不是自动证明“没有影响”。先检查核心流程和高风险分支，执行中发现的新相邻风险加入清单；改变清单会使旧结果失效，工具要求重新确认环境与执行。

没有文档的预期可以依据明确用户目标或改动前的已接受行为，并注明推断。无法确定时将有关场景阻塞，不能将猜测包装成产品缺陷。

## 执行和判断

每项至少保存真实动作、预期与实际、当前版本、证据及检查范围。用户旅程要到可核实的终态：创建后重新读取；通知检查测试收件箱并点回正确对象；任务要观察输出或状态变化。仅能观察界面的场景明确写出这一限制。

检查可见 UI、内容、反馈、控制台与请求失败。时间阈值须来自项目目标或实际测量；视觉感觉慢不等于压测结果。无障碍观察不等于完成所有标准的自动审计。体验建议与功能错误分别记录，避免人为抬高缺陷数。

复现时保持相同数据和前提，有写入的步骤用新测试数据隔离，避免重复操作本身污染结论。初次失败后再尝试：

- 两次及以上失败、没有成功：`fail`，说明一致的症状。
- 只观察一次或无法再次尝试：`observed`，保留原因和证据。
- 同一条件下成功与失败都出现：`flaky`，保存完整尝试列表与次数。
- 环境、需求或依赖缺失：`blocked`，描述继续验证需要什么。
- 有意不执行：`skipped`，说明理由，不算通过。

同一轮次、同一环境的重新记录要携带先前尝试；不能用后来一次 pass 抹掉失败。发现属于既有版本时 attribution 可记 preexisting；归属不明用 unknown，不能仅凭 diff 看起来相关就断言由 PR 引入。

## 证据的粒度

静态错位、文案等问题一张截图即可。多步交互记录关键步骤前后截图，并关联 step；有录屏能力时保存完整复现过程。API/CLI/任务使用实际响应、退出码、测试输出或本地状态记录，不能以代码片段替代运行结果。

注册工具复制证据到私有 run 目录，记录 SHA-256、大小、类型、场景、步骤和轮次；没有文件、文件被改、跨场景或旧环境的证据会被拒绝。工具只校验文件及关联，**不能验证图片内容真实反映了预期，也不会从视频生成回放脚本**。

场景声明 required_evidence。能力不足时记录 evidence_gaps 并采用其他实际证据；缺口会阻止无保留的 READY_WITHIN_SCOPE。不要为了满足类型检查制造空白图、占位日志或伪视频。

严重度用 critical / high / medium / low，分别说明核心流程阻断或数据损失、主要能力不可用、存在替代路径的问题、轻微体验/视觉问题。标注归属 introduced / preexisting / unknown。报告实际观察，不凑缺陷数量。

## 命令执行记录

`exec` 在 context 的工作区启动实际命令，保存开始与结束、代码指纹、退出码和日志。未完成命令保留 exit_code=null；超时终止本命令进程组并返回 124，中断返回 130。启动失败也保留未完成记录，检查其影响后用 interrupt-command 收尾。

浏览器驱动的命令有时在输出中报告错误却仍返回0；逐次检查实际响应和页面状态，文件证据以真实存在为准。

不要把长驻开发服务交给有超时的 exec 当作测试套件；由宿主管理服务生命周期，登记真实启动证据即可。执行测试时凭据放入环境，不写进 argv；工具会屏蔽常见环境密钥和 Authorization 值，但不能保证脱敏所有业务数据。交付前仍要查看实际证据。
