# 首次使用：先选择部署角色

标准架构是[云端控制服务 + 独立 AI Runner](../architecture/system-architecture.md)。你不需要在每台电脑运行一套网站。

## 已有 OpenLore 网站，只把新电脑作为 AI Runner

1. 向管理员取得网站地址，在自己电脑准备 Node.js 和已登录的 Codex CLI 或 Gemini CLI。
2. 按[AI Runner 接入](ai-executors.md)构建当前 Worker 程序，添加执行器并下载配对配置。
3. 只启动 `worker` 进程，确认网站显示在线，测试连接并验证一次实际任务。

**这台电脑无需运行 `npm run dev`、Python 采集器或数据库。**当前仍需从源码构建 Runner，独立下载安装包尚未提供；这是现有分发流程的限制。

## 还没有网站，准备自行部署

按[控制服务部署](server-deployment.md)在常驻机器上安装并启动网站、采集环境和数据库，再按上述步骤接入一个或多个执行机。AI CLI 可以留在自己的电脑，不必装到服务器。

## 想修改代码或在同一电脑调试

按[开发者指引](development.md)准备完整环境，运行 `pnpm dev` 或 `npm run dev`。这个命令启动后端和 Vite，属于整站开发流程，不会替你启动独立 Runner。

需要模拟正式拓扑时，在另一终端独立运行 Worker，配对地址指向后端 `http://127.0.0.1:8767`。也可用 `local` 模式快速调试，它由后端直接调用本机 CLI。

## 跑通第一条业务流程

以下操作在云端网站完成，服务器和至少一个 AI 执行器应已就绪。

1. **系统设置**：添加 GitHub 仓库连接，填写仓库、目标分支和具有目标内容读写权限的 Token，测试连接。首轮建议用试用仓库。
2. **来源采集**：启用或添加一个来源，手动触发采集，在“内容池”确认准入后的文章入库。
3. **流水线任务**：选择来源范围、AI 执行器、审核 Skill、归档仓库和路径；首次可关闭深度调研并减少选文数量。
4. 点击“立即运行”，到“运行记录”检查流水线和 AI 调用。任务会真实写入 GitHub；入选文章归档成功后在“每日精选”阅读。
5. 如需群汇报，添加通知通道，再到“汇报推送”配置计划、任务和目标通道；手动发送会真实调用 Webhook。

网页能打开、Runner 在线、CLI 能调用、归档成功是不同的验证环节。环境自检和 `--version` 检查不代替实际任务验收。
