# OpenLore 功能与流程

**来源采集 → 内容池 → 流水线任务 → 汇报推送**。

| 菜单       | 路由         | 职责                                                                    |
| ---------- | ------------ | ----------------------------------------------------------------------- |
| 每日研报   | `/`          | 阅读已归档的深度研报                                                      |
| 来源采集   | `/sources`   | 配置采集周期、关键词与启用状态，独立入池                                |
| 内容池     | `/pool`      | 按首次入库时间查看全部文章                                              |
| 流水线任务 | `/pipelines` | 按主题进行 AI 审核、调研与 GitHub 归档                                  |
| 汇报推送   | `/reports`   | 建立多个汇报方案，分别汇总任务、生成简报并发送到不同群                  |
| 运行记录   | `/runs`      | 三个页签：流水线任务、推送日志、AI 调用日志；从业务运行直接打开关联调用 |
| 系统设置   | `/settings`  | 管理仓库、AI 执行器、通知通道与系统诊断                                 |

部署关系见[系统架构与 SVG 图](../../architecture/system-architecture.md)。云端负责采集、编排、归档与通知；AI Runner 独立连接云端执行任务。

来源与任务独立调度。任务评估来源范围内尚未完成调研的池内文章，按评分选择 M 篇调研；日期窗口由来源准入控制。汇报等待所选任务完成 GitHub 归档后，合并结果发送。
