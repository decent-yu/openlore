# 06 汇报推送

入口 `/reports`。支持多个独立汇报方案，例如 Agent 日报发群 A、前端日报发群 B。同一个任务可以加入多个方案。

## 方案配置

每个方案配置名称、一个或多个流水线任务、目标群通道、简报 Skill、Cron、时区和启用状态。任务本身不生成简报；汇报方案读取已归档结果后调用简报 Skill。

每个方案独立保存、编辑、停用、删除、预览与发送。删除方案不删除任务和历史推送记录。旧的单一汇报配置迁移为「每日工作汇报」方案。

## 汇总规则

- 按方案时区读取当天完成归档的成功运行，包括跨午夜开始、当天完成的任务。
- 所选任务全部成功完成后才发送；未运行、运行中或最新运行失败时等待。
- 定时触发后未就绪，在当天继续检查。等待状态独立持久化，群 A 的未完成任务不阻塞群 B 的方案。
- 合并任务当天多次成功运行的结果，不同任务的相同文章去重。没有新增精选时跳过发送。
- 预览展示结构化任务结果，发送时通过所选简报 Skill 汇总文字；未选择 Skill 或可选汇总失败时使用结构化结果。
- 每个方案有独立的发送锁与防重标识，同一方案当天成功发送后不重复推送。

## 接口与存储

- `GET /api/v1/reports`：列出方案。
- `POST /api/v1/reports`：创建方案。
- `PUT /api/v1/reports/:id`：编辑方案。
- `DELETE /api/v1/reports/:id`：删除方案。
- `GET /api/v1/reports/:id/preview`：预览。
- `POST /api/v1/reports/:id/send`：手动发送。

方案与等待日期存于 `report_plans`。推送记录保存方案标识、名称、目标通道与结果，可在运行记录页查看。
