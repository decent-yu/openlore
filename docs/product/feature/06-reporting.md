# 06 汇报推送

入口 `/reports`。支持多个独立汇报方案，例如 Agent 日报发群 A、前端日报发群 B。同一个任务可以加入多个方案。

## 方案配置

每个方案配置名称、一个或多个流水线任务、目标群通道、卡片标题、Markdown 正文模板、Cron、时区和启用状态。汇报方案直接读取已归档结果并按模板渲染，不调用 AI，也不依赖执行器在线。

每个方案独立保存、编辑、停用、删除、预览与发送。删除方案不删除任务和历史推送记录。

## 汇总规则

- 按方案时区读取当天成功归档的深度研报，包括跨午夜运行以及人工调研的成果。
- 自动定时推送要求所选任务全部成功完成；未运行、运行中或最新运行失败、取消时等待。手动推送直接发送当前预览，不受任务状态或当日已发送条件限制。
- 定时触发后未就绪，在当天继续检查。等待状态独立持久化，群 A 的未完成任务不阻塞群 B 的方案。
- 合并任务当天多次成功运行的结果，同一任务的同一文章仅展示最新研报；不同任务对同一原文生成的研报分别计数，总数与展示的标题数一致。没有新归档研报时自动推送跳过；手动仍可发送空结果预览。
- 预览和发送使用同一模板渲染函数。数据未变化时，预览正文与发送正文一致。Wiki 链接由仓库配置解析，优先研报、其次正文；未配置时保留归档或原文链接。
- 每个方案有独立的发送锁。定时推送在同一方案当天成功发送后跳过；手动推送允许重复发送，每次生成独立事件标识并保存推送记录，便于测试。手动发送成功后，定时任务同样视为当天已发送。

## 可配置模板

编辑方案时分别修改卡片标题与 Markdown 正文，恢复默认并查看飞书卡片模拟；保存后的“预览”展示真实数据。蓝色区域是飞书卡片标题，白色区域是正文。标题和正文来自与发送端共用的卡片生成函数，细节排版以飞书客户端为准。模板支持：

飞书/Lark 使用 JSON 2.0 卡片的 `markdown` 富文本组件呈现正文，避免旧版 `div.text.lark_md` 将标题和列表标记直接显示为文字。模板中的 `#` 至 `######` 标题在发送及模拟时统一转换为加粗分组标题，代码围栏中的内容保留；文章之间保留空行。通用 Webhook 继续接收原始 Markdown 正文。

| 变量                | 内容                                     |
| ------------------- | ---------------------------------------- |
| `{{report_name}}`   | 汇报名称                                 |
| `{{date}}`          | 按方案时区计算的日期                     |
| `{{task_count}}`    | 流水线任务数                             |
| `{{article_count}}` | 展示的已归档研报数                       |
| `{{deep_count}}`    | 深度调研篇数                             |
| `{{content}}`       | 按任务分组的研报标题链接 |

默认卡片标题为 `{{report_name}}`，直接显示方案名称；也可以填写固定标题，或组合日期与统计变量。标题是单行纯文本，不支持 `{{content}}`。

默认正文模板：

```markdown
日期：{{date}}

汇总 {{task_count}} 个流水线任务，共 {{article_count}} 篇已归档研报。

{{content}}
```

模板必须包含 `{{content}}`，不支持的变量在编辑页和服务端均报错。文章调研与 GitHub 仓库研读统一仅展示标题链接：优先提取对应已归档研报正文的一级标题；缺少有效标题时回退为原文标题。不展示初审定位、摘要或重复的“含深度调研”标识，不额外调用 AI。飞书/Lark 通知使用预览中的卡片标题与正文；发送记录也保存相同标题。正文中的 Markdown 标题仅属于正文，不会覆盖卡片顶部标题。

## 接口与存储

- `GET /api/v1/reports`：列出方案。
- `POST /api/v1/reports`：创建方案。
- `PUT /api/v1/reports/:id`：编辑方案。
- `DELETE /api/v1/reports/:id`：删除方案。
- `GET /api/v1/reports/:id/preview`：预览。
- `POST /api/v1/reports/:id/send`：发送汇报；请求体 `{"force":true}` 忽略任务就绪状态并允许重复发送，页面手动推送默认携带，省略时保持自动等待与当天防重。

方案与等待日期存于 `report_plans`。推送记录保存方案标识、名称、目标通道与结果，可在运行记录页查看。
