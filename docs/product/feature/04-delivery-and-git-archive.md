# 文件归档、GitHub 同步与通知

## 连接与组路由

用户在工作区设置中提前配置 GitHub 仓库、Token 和默认分支。采集组只选择 `repository_connection_id` 并填写路由，如 `/docs/agent-leaning`；通知同样引用预配置连接。修改一次连接即可供后续批次复用，不在每组复制秘密。

`/docs/agent-leaning` 被规范化为仓库相对目录 `docs/agent-leaning`，不是本机绝对路径。拒绝 `..`、空根目录和跨组重叠路由。仓库不存在、分支不可写、权限不足在连接检查和运行预检时呈现；运行保持 blocked 并可恢复。

## 仓库里的实际内容

以下是一次入选两篇文章、随后完成一项深度调研的示例：

```text
/docs/agent-leaning/
├── README.md                             # 全部已归档文章与调研的导航
├── articles/
│   ├── a-001/
│   │   ├── source.md                     # 清洗后的原文，保留原语言、代码与图片链接
│   │   ├── analysis.md                   # 中文摘要、关键事实、技术取舍与相关理由
│   │   └── metadata.json                 # 来源、稳定 ID、版本、评分与生成依据
│   └── a-002/
│       ├── source.md
│       ├── analysis.md
│       └── metadata.json
├── digests/2026/10/
│   └── 2026-10-15_090000_run-001.md       # 本批新增/更新内容及排除、失败、延后统计
├── research/
│   └── r-001-agent-reliability/
│       ├── report.md                     # 深入调研报告，带事实、推断、引用与限制
│       └── sources.json                  # 种子与新增资料、读取状态、证据位置
└── .openlore/manifest.json                # 系统管理文件与摘要值、批次记录
```

可阅读[完整示例目录](examples/repository-output/docs/agent-leaning/README.md)。示例为人工构造的虚拟内容，不是对真实文章的引用或已完成的采集。

- source.md 保存取得的正文 Markdown，不上传原始 HTML、登录数据或临时调试文件；不把 AI 生成文字写成原文。短评本身可保存，但应注明类型，不冒充外链全文。
- analysis.md 默认包含 3–5 条摘要、关键事实与证据、技术取舍、适用条件、与组主题的关系、内容缺口和原文链接。
- metadata.json 保存 canonical URL、作者、发布时间、来源关联、内容 hash、组规则修订、模型/提示词版本、评分与处理时间；每次轮询的检查时间只保存在本地，不制造无意义 Git diff。
- README.md 索引保留历史内容；简报记录本次发生的变化。每个 article_id、research_id 的路径稳定，不随标题修改而改名。
- 图片保留链接，首期不镜像二进制媒体和交互页面。研究报告的第三方完整材料保存在本地证据库，仓库中保留报告与来源清单。

## 每次到底同步多少文件

| 本次结果 | 默认文件变化 |
| --- | --- |
| 新入选 N 篇，未运行调研 | 每篇 3 个文件 + 本批简报 + README + manifest；首次为 `3N + 3` 个文件，例如 2 篇是 9 个 |
| 更新一篇已有文章 | 更新该文章有变化的文件，新增本批简报，更新 README 和 manifest；路径不变 |
| 完成一项调研 | report.md、sources.json、README、manifest，通常 4 个；不重复生成普通简报 |
| 无新增、无正文更新、无新研究 | 不创建文件、空简报或空提交；运行记录仅留在本地 |
| 全部候选不匹配 | 本地保留排除原因；仓库无变化，默认不推送 |
| 部分条目失败，但有成功入选 | 同步有效内容，简报标明部分失败；失败条目恢复后产生下一批变更 |

没有变化的文件不会重写。已发布简报保持为历史批次快照；文章笔记与研究报告可沿原路径更新，修订通过 Git 历史追踪。

## GitHub 写入流程

校验连接与路由 → 冻结本批文件包及目标快照 → 读取目标分支最新树 → 比较管理清单和文件摘要值 → 一批新增/更新形成一个提交 → 更新目标分支 → 核对实际文件 → 记录成功 → 发送可选通知。

- Token 使用目标仓库内容读写权限；运行器负责 GitHub 写入，Codex/Gemini 不直接获得 Token 或修改目标仓库。
- 修改范围是本组路由下系统管理的文件。首次遇到非空目录可并存，但同名非管理文件不会覆盖；连接预检和首次预览列出冲突。
- 用户编辑过系统管理文件且与新生成内容冲突时，保留双方并报告 conflict。用户在运行详情选择“保留远端”“采用生成版”或“指定新路径”，不会由 AI 猜测覆盖。
- 手工笔记可放在未被 manifest 管理的位置，系统不修改。文章未再次入选、来源停用或组暂停都不删除历史文件。
- 同一组和同一仓库分支分别串行交付；使用远端最新 base_tree，保留其他文件，更新引用不使用 force。
- 网络超时先检查 manifest 中的 batch_id 和文件摘要值，确认是否已经提交，避免重复提交。

## 通知是归档后的可选出口

首期固定实现通用 JSON Webhook，接收方返回 HTTP 2xx 为成功；未绑定通知连接时为 skipped。专有平台返回码映射后续通过独立适配器增加，当前不留“等待选择平台”的实现缺口。

```json
{
  "event": "collection.completed",
  "event_id": "group-agent:run-001",
  "group": {"id": "group-agent", "name": "Agent 相关知识"},
  "status": "success",
  "counts": {"selected": 2, "failed": 0, "deferred": 0},
  "summary": "新增两篇技术分析，已同步仓库。",
  "repository_url": "https://github.com/example/team-knowledge",
  "commit_sha": "示例提交标识",
  "document_path": "docs/agent-leaning/digests/2026/10/2026-10-15_090000_run-001.md"
}
```

研究完成使用 `research.completed`。相同事件重试沿用 event_id 和 `Idempotency-Key`；接收方未实现幂等时只能做到尽量防重，不能承诺严格一次投递。

## 失败恢复与用户动作

| 场景 | 系统行为 |
| --- | --- |
| Token 失效、仓库或分支权限不足 | blocked；连接页修复后重试原文件包，不重复执行 AI |
| 远端只有无关路径更新 | 重新基于最新树提交，最多三次；持续竞争转待重试 |
| 管理文件发生冲突 | conflict；界面展示具体文件与差异，等待上述显式决策 |
| GitHub 成功、Webhook 失败 | 只重试通知；仓库成功状态不回退 |
| 写入结果不明 | unknown；查询远端核对，无法确认则保留状态，不盲目重复写 |
| 修改连接或组路由 | 新运行使用新配置；既有运行维持快照，撤销凭据立即阻止其未完成动作 |

接口与并发实现见[处理与同步设计](../../design/processing-and-delivery.md)。

## 验收

在预配置仓库中使用 `/docs/agent-leaning` 跑通 2 篇入选的 9 文件批次；重跑零变化；原文更新只改变对应文章及新简报；完成一次深度研究新增研究产物。验证另一组不同路由、Token 失效、人工改文件、并发提交与消息单独补发。
