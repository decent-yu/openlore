# 文件归档、GitHub 同步与通知

## 连接与组路由

用户在工作区设置中提前配置 GitHub 仓库、Token 和默认分支。采集组只选择 `repository_connection_id` 并填写路由，如 `/docs/agent-leaning`；通知同样引用预配置连接。修改一次连接即可供后续批次复用，不在每组复制秘密。

`/docs/agent-leaning` 被规范化为仓库相对目录 `docs/agent-leaning`，不是本机绝对路径。拒绝 `..`、空根目录和跨组重叠路由。仓库不存在、分支不可写、权限不足在连接检查和运行预检时呈现；运行保持 blocked 并可恢复。

## 面向阅读的归档目录

归档按“日期批次 → 文章”组织，不再按 articles/digests/research 分拆同一篇文章。每篇使用一个目录，将正文、可选调研和配图放在一起：

```text
/docs/agent-leaning/
├── README.md                         # 批次导航
├── 20261015-01/
│   ├── README.md                     # 本批文章导航，程序生成
│   ├── digest.md                     # 可选：勾选后生成的批次简报
│   ├── 01-agent-recovery/
│   │   ├── article.md                # 导读 + 整理原文 + 出处
│   │   ├── research.md               # 可选：仅针对本篇的深入调研
│   │   └── assets/                   # 本篇及其调研使用的全部配图
│   └── 02-context-evidence/
│       ├── article.md
│       ├── research.md               # 可选
│       └── assets/
├── 20261015-02/                       # 同一天下一次有效采集
└── .openlore/manifest.json            # 隐藏的路径/摘要映射，供同步恢复
```

[阅读新示例](examples/README.md)。示例直接放在 examples/ 下，不再嵌套 repository-output/docs/agent-leaning；内容为人工构造，仅演示阅读结构。

### 文件与链接

- article.md 开头说明标题、来源、作者、日期与原文地址；随后是明确标注的 AI 导读、整理原文、图注和内容缺口。原文与 AI 推断不能混写。
- research.md 与 article.md 在同一目录互相链接，参考资料直接列在报告中；图片统一引用 `assets/...`。
- 元信息、评分、证据片段和运行诊断保留在本地数据库，必要的恢复映射进入隐藏 manifest，不为读者生成多份 metadata.json/source.md/analysis.md。
- 目录标题采用简短英文 slug，文件内保留完整文章标题；分类标签写在文章与导航中，不再增加分类文件夹。
- 批次 README 只是文章链接与调研状态。digest.md 是额外 AI 简报，只有勾选才生成，两者职责不同。

### 编号、更新和重试

- 按组工作区时区分配 `YYYYMMDD-NN`；同组同日序号递增，原子分配。有效批次冻结时分配，重试不重新取号；失败保留号码，允许空档。
- 首次入选按确定的结果顺序分配 `01-slug`、`02-slug`；序号和 slug 固定，标题变化或调研完成都不重命名目录。
- 同一文章后续有实质变化时更新最初归档目录；新批次 README/digest 以相对链接指向它，不复制文章与图片。没有新入选或更新内容则不创建批次目录。
- 调研与简报是对所属批次的后续补齐，保留采集批次 ID、另外使用交付事件 ID。晚到研究更新 article.md 的关联链接与批次导航，不改当时已发布的简报文字。
- 关闭产物开关只影响新任务，不自动删除已有文件。生成出的旧图片不自动清理，以免破坏历史链接；后续可显式清理未引用资源。

## 文件数量按实际产物计算

首次新入选 N 篇、归档 I 个图片文件、生成 R 篇逐篇研究、D 份简报（0 或 1），文件数为 **N + I + R + D + 3**：最后 3 个是路由 README、批次 README、隐藏 manifest。

例如两篇文章各一张图，两个可选项都关闭，共 7 个文件；简报开启、两篇研究全部完成，共 10 个。若研究异步完成，先同步文章与简报 8 个文件，再按完成情况补齐研究和相关导航。无图时不创建空 assets 目录。

无变化重跑仍是零提交；已有文章更新只提交真正变化的文件。图片数量不固定，因此不再采用“每篇固定三个文件”的规则。

## GitHub 写入流程

校验连接与路由 → 冻结本批文件包及目标快照 → 读取目标分支最新树 → 比较管理清单和文件摘要值 → 一批新增/更新形成一个提交 → 更新目标分支 → 核对实际文件 → 记录成功 → 发送可选通知。

- Token 使用目标仓库内容读写权限；运行器负责 GitHub 写入，Codex/Gemini 不直接获得 Token 或修改目标仓库。
- 修改范围是本组路由下系统管理的文件。首次遇到非空目录可并存，但同名非管理文件不会覆盖；连接预检和首次预览列出冲突。
- 用户编辑过系统管理文件且与新生成内容冲突时，保留双方并报告 conflict。用户在运行详情选择“保留远端”“采用生成版”或“指定新路径”，不会由 AI 猜测覆盖。
- 手工笔记可放在未被 manifest 管理的位置，系统不修改。文章未再次入选、来源停用或组暂停都不删除历史文件。
- 同一组和同一仓库分支分别串行交付；使用远端最新 base_tree，保留其他文件，更新引用不使用 force。
- 网络超时先检查 manifest 中的 batch_id 和文件摘要值，确认是否已经提交，避免重复提交。

## 通知是归档后的可选出口

首期固定实现通用 JSON Webhook，接收方返回 HTTP 2xx 为成功；未绑定通知连接时为 skipped。专有平台返回码映射后续通过独立适配器增加，当前不留“等待选择平台”的实现缺口。

```json
{
  "event": "collection.completed",
  "event_id": "group-agent:run-001",
  "group": {"id": "group-agent", "name": "Agent 相关知识"},
  "status": "success",
  "counts": {"selected": 2, "failed": 0, "deferred": 0},
  "summary": "新增两篇技术分析，已同步仓库。",
  "repository_url": "https://github.com/example/team-knowledge",
  "commit_sha": "示例提交标识",
  "document_path": "docs/agent-leaning/20261015-01/README.md"
}
```

逐篇研究完成使用 `research.completed` 并包含 article_id 与该篇 research.md 路径。相同事件重试沿用 event_id 和 `Idempotency-Key`；接收方未实现幂等时只能做到尽量防重，不能承诺严格一次投递。

## 失败恢复与用户动作

| 场景 | 系统行为 |
| --- | --- |
| Token 失效、仓库或分支权限不足 | blocked；连接页修复后重试原文件包，不重复执行 AI |
| 远端只有无关路径更新 | 重新基于最新树提交，最多三次；持续竞争转待重试 |
| 管理文件发生冲突 | conflict；界面展示具体文件与差异，等待上述显式决策 |
| GitHub 成功、Webhook 失败 | 只重试通知；仓库成功状态不回退 |
| 写入结果不明 | unknown；查询远端核对，无法确认则保留状态，不盲目重复写 |
| 修改连接或组路由 | 新运行使用新配置；既有运行维持快照，撤销凭据立即阻止其未完成动作 |

接口与并发实现见[处理与同步设计](../../design/processing-and-delivery.md)。

## 验收

在 `/docs/agent-leaning` 验证日期序号、逐篇目录、article/research 互链及图片本地化；两篇各一张图分别验证 7 文件基础批次和 10 文件完整批次。验证正文/图片变更沿旧路径更新、异步补齐不另建采集批次、同日第二批不撞号，最后覆盖既有同步冲突和通知恢复场景。
