# 内容处理

将统一采集结果转换成按组筛选的知识内容，再生成可直接同步到仓库的文件包。

## 职责与流程

读取[采集结果](02-content-collection.md) → 检查正文质量 → 内容清洗与重复合并 → 按组判断相关性 → 生成摘要 → 渲染文件包 → 交给[文件同步](04-delivery-and-git-archive.md)。

- 采集层负责取得正文；本模块负责清洗整理、业务筛选和提炼。正文缺失时请求补抓，不将标题扩写成“全文摘要”。
- 依据[采集组](01-source-configuration.md)的关注描述、筛选偏好及组内各来源关键词分别处理。
- 同一内容可进入多个组；采集去重不等于组内筛选或交付防重。

## 统一输入与输出

| 输入 | 约定 |
| --- | --- |
| 内容 | 统一条目及其内容版本、完整度、来源与原始依据 |
| 采集组 | 组标识、配置版本、关注描述、来源集合与逐来源关键词 |
| 处理配置 | 摘要语言、模型配置引用、处理规则与提示词版本 |

| 输出 | 约定 |
| --- | --- |
| 筛选结果 | 每条内容的入选、排除或待补全状态及原因 |
| 知识条目 | 稳定文章标识、来源链接、主题、短摘要、关键事实、相关理由与内容缺口 |
| 文件包 | 组标识、批次标识、相对文件路径、UTF-8 文件内容、内容摘要值与管理清单 |
| 运行结果 | 成功、部分成功或失败，以及可单独重试的条目 |

输入输出及文件包约定见[处理与同步设计](../../design/processing-and-delivery.md)。

## 本期处理规则

- 清理导航、样式与明显重复内容，保留有意义的段落、代码、图片引用和原文链接。
- 按稳定文章标识合并重复，内容摘要值用于识别更新；同一文章从多个来源发现时保留所有出处。
- 关键词作为组内关注信号，结合关注描述判断相关性；严格关键词匹配规则尚待细化。保留筛选理由，便于调整配置。
- 摘要以取得的正文为依据；原文事实与解释分开，标注未读取的图示、媒体或付费部分。
- 未取得有效正文或模型失败的条目进入待处理结果，不伪装成成功；其他有效条目可继续生成文件。
- 组配置、内容或处理规则变化时允许重新处理。文件包一旦生成即固定，交付重试复用该包，不重复调用模型生成不同内容。

## 文件产物

| 文件 | 内容与更新方式 |
| --- | --- |
| `articles/<article_id>.md` | 一篇文章在本组中的摘要、关键事实、相关理由、元信息与出处；更新沿用同一路径 |
| `digests/<batch_id>.md` | 本次入选条目的摘要与链接；批次重试保持路径和内容不变 |
| `index.md` | 当前组已归档内容的索引，由持久记录生成，不能只包含本批新增内容 |
| `.openlore-manifest.json` | 本组管理的文件、内容摘要值、生成批次等同步信息，不含凭据 |

以上均相对于组配置的 Git 路径。首期产物为文本文件与图片链接，不承诺归档原网页的交互效果。

## 扩展与验收

- 内容规范化、主题判断、摘要生成、文件渲染分别组织；模型提供者独立适配，统一返回结构化结果。
- 初期使用一个模型适配器和一套 Markdown 模板；后续替换模型不改变文件包接口。
- 两个组使用同一来源、不同关键词时，能得到各自的筛选结果和文件包。
- 相同输入重试复用已有结果；正文更新沿用文章路径；部分失败可单独恢复，不丢失既有索引。
