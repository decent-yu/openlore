# 内容处理、本地 AI 与深度调研

## 本期交付

每个入选文章生成**可读原文 Markdown、中文分析笔记和元信息**；每批生成一份简报。用户还可以基于一篇或多篇已采集文章发起深入调研，形成带证据的新报告。具体文件结构见 [04](04-delivery-and-git-archive.md)。

本地服务通过已经安装、登录的 Codex CLI 或 Gemini CLI 执行 AI 任务；每次任务启动独立非交互进程，完成后退出。常驻的是 OpenLore 的调度与状态管理，不是无限增长的聊天会话。推理通常仍调用对应服务，受账号权限与额度限制。

## 普通文章处理

1. 取得 02 的候选和有效正文；清理导航与重复段落，保留代码、标题结构、图片链接与原始出处。
2. 识别稳定文章及内容版本；同一文章的多个来源保留关联。各组独立筛选，不因其他组已处理而跳过。
3. 对标题与正文做 Unicode NFKC、大小写和空白归一化，再应用关键词规则。关键词按归一化后的字面子串/短语匹配，不支持隐含正则。
4. 通过该组 AI 执行器评估相关性与质量；有效结果达到门槛后排序、限量，随后生成分析笔记。
5. 校验证据和输出结构，持久化决策与文件包；交付重试直接使用固定文件包。

### 筛选规则与默认值

| 配置 | 明确行为 |
| --- | --- |
| 排除词 | 在对应来源的标题或正文中命中任意排除词，该来源关联不符合本组要求 |
| `semantic`（默认） | 正向关键词作为关注提示，不按字面命中淘汰；AI 综合组描述、偏好与对应来源关键词判断 |
| `any` | 对应来源正向关键词非空时至少命中一个，再进行 AI 评估 |
| `all` | 对应来源正向关键词非空时全部命中，再进行 AI 评估 |
| 多来源指向同一文章 | 只要一个已配置来源关联通过自己的条件即可进入本组；记录实际匹配来源，不混用另一来源的关键词 |
| AI 门槛 | relevance ≥ 70 且 quality ≥ 50；两者范围 0–100，默认可配置 |
| 排序 | 应用计算 `0.7 × relevance + 0.3 × quality`，再按发布日期降序、稳定文章 ID 排序；无日期排在同分有日期之后 |
| 入选上限 | 默认每批 10 篇；不为了凑数降低门槛，合格但超额者延后，下批复用结果 |

质量评分依据技术细节、证据、实现或实验、可复用性，不能仅按热度判定。每个评分附原文证据片段与理由；模型不决定实际文件路径和仓库权限。

### 内容不完整与长文章

- 正文缺失、验证页或明显付费摘要进入 pending，默认不生成“全文分析”；图示/附件未解析则在笔记中明确说明，不推断图中结论。
- 超过单次输入预算时按章节分块，默认每块最多 12,000 字符、重叠最多 500 字符，最多 8 块；逐块提取事实后再综合，保留片段来源。
- 超过总上限的内容标记 `content_too_large`，提供原文和失败原因，不静默截断后作为全文入选。用户可调整预算重试。
- JSON 结构或引用校验失败自动修复一次；仍失败则待处理。普通单次 AI 调用默认超时 120 秒，单篇含分块总预算 10 分钟。

## AI 工作区配置与运行

工作区预先保存 AIProfile：provider、CLI 绝对路径、模型、超时、任务策略；采集组引用或继承默认配置。首期同时实现 `codex_cli` 与 `gemini_cli` 两个适配器，同一任务只调用所选的一种。

- 首次设置完成 CLI 登录与最小非交互 JSON 测试，确认运行账户、PATH 和执行能力；任务中不弹出交互式确认。
- 认证过期、额度不足或不支持的版本返回可识别状态，在设置页处理后恢复，不以空摘要替代；不会自动切换到另一个计费方式。
- 每项任务使用独立工作目录和证据文件；子进程不接收 GitHub Token、Webhook 或仓库写权限。模型返回内容，应用负责渲染文件及同步。
- 记录 CLI 版本、实际模型、输入内容版本、提示词版本、耗时及可获得的 usage。CLI 未返回用量时标记 unknown，不假装为零。
- 普通处理仅使用提供的材料；不用网络搜索引入未经核实的新事实。全文、提示词与结果缓存保存在本地，按文章/组规则/执行器版本复用。

官方能力与精确调用方式见[本地服务与 AI 设计](../../design/local-service-and-ai.md)。本次只核查官方文档和本机 CLI 帮助，未代用户执行模型推理。

## 深度调研：可执行的有限流程

入口：内容库勾选 1–3 篇文章 → “深入调研” → 填写问题，选择目标采集组 → 预览预算 → 开始。问题为空时使用默认目标：解释核心机制、比较技术取舍、核对适用场景并列出待验证问题。

| 项目 | 首期默认策略 |
| --- | --- |
| 触发 | 手动；组内可主动开启 `auto_top1`，每天仅对最高分且总分 ≥ 85 的一个新入选文章运行一次 |
| 模式 | `local` 只分析已采集材料；默认 `linked_web` 可读取种子文章直接引用的公开资料 |
| 扩展范围 | 从文章中实际发现的链接选择，默认最多 6 个新页面、链接深度 1；不让模型虚构 URL |
| 网络能力 | 复用 web_page；无法读取、需要登录或媒体未解析则记录证据缺口，不自动进入无限浏览器探索 |
| AI 过程 | 规划问题与引用需求 → 应用获取材料 → 综合分析 → 校验与一次修复；最多 3 次 AI 调用，任务总时限 15 分钟 |
| 输出 | 报告、来源清单与抓取状态，进入原采集组路由下的 research 目录 |
| 失败或预算耗尽 | 已有证据形成明确标注的部分报告；没有有效证据则失败，不自动发布空报告 |

`linked_web` 是基于种子引用的扩展研究，不承诺全网搜索。通用搜索属于后续可接入能力；本期的深入调研流程无需额外搜索 API Key 即可执行。

报告固定包括：问题与结论、原文事实、机制解释、方案比较、适用条件、反例/限制、对团队的建议、引用与未验证项。区分原文结论、交叉验证结果和 AI 推断。可为同一研究问题点击“更新调研”，保持 research_id 和路径稳定；新问题创建新研究。

普通简报无需等待深度调研。调研完成后单独生成文件包，同步报告与索引；自动调研以组、种子内容版本和问题为身份，不能同一篇每天重复跑。

## 输入输出与文件冻结

输入：组配置快照、文章版本与证据、AIProfile、处理预算；输出：逐条 selected/excluded/pending/deferred 及原因、知识条目、研究报告、文件包和错误。详细字段见[处理与同步接口](../../design/processing-and-delivery.md)。

相同输入的成功结果复用；需要更新处理时创建新业务运行，不能把重试当成重新生成。任何 GitHub/消息重试只重用冻结的 batch_id、路径和文件内容。

## 验收

用固定样本验证 any/all/semantic、排除词、多来源归属和 70/50 门槛；实际分别验证一次 Codex 和 Gemini 的非交互 JSON 处理。对同一文章在两个组产生不同笔记；深度调研必须有可核对引用、预算截止和缺口说明，且能独立归档、重试与更新。
