# 内容处理、本地 AI 与深度调研

## 本期交付

每篇入选文章形成一个阅读单元：**article.md + assets/**。article.md 内清楚区分中文导读与整理后的原文；勾选逐篇深度调研时，在同一目录生成 research.md。批次简报是独立复选项。目录以批次和文章组织，详见 [04](04-delivery-and-git-archive.md)。

本地服务通过已经安装、登录的 Codex CLI 或 Gemini CLI 执行 AI 任务；每次任务启动独立非交互进程，完成后退出。常驻的是 OpenLore 的调度与状态管理，不是无限增长的聊天会话。推理通常仍调用对应服务，受账号权限与额度限制。

## 普通文章处理

1. 取得 02 的候选和有效正文；清理导航与重复段落，保留代码、标题结构、配图、图注与原始出处；所有配图交给图片归档能力保存，不能只保留远端图片链接。
2. 识别稳定文章及内容版本；同一文章的多个来源保留关联。各组独立筛选，不因其他组已处理而跳过。
3. 对标题与正文做 Unicode NFKC、大小写和空白归一化，再应用关键词规则。关键词按归一化后的字面子串/短语匹配，不支持隐含正则。
4. 通过该组 AI 执行器运行文章整理 skill 的评估阶段，判断相关性与质量；有效结果达到门槛后排序、限量，随后调用文章整理 skill，生成适合阅读的内容、分类标签及可用的标题建议。
5. 下载并校验该文章的全部配图，将引用替换为 assets/ 相对路径；校验 Markdown、证据与文件包，交付重试直接使用固定文件包。

### 筛选规则与默认值

| 配置 | 明确行为 |
| --- | --- |
| 排除词 | 在对应来源的标题或正文中命中任意排除词，该来源关联不符合本组要求 |
| `semantic`（默认） | 正向关键词作为关注提示，不按字面命中淘汰；AI 综合组描述、偏好与对应来源关键词判断 |
| `any` | 对应来源正向关键词非空时至少命中一个，再进行 AI 评估 |
| `all` | 对应来源正向关键词非空时全部命中，再进行 AI 评估 |
| 多来源指向同一文章 | 只要一个已配置来源关联通过自己的条件即可进入本组；记录实际匹配来源，不混用另一来源的关键词 |
| AI 门槛 | relevance ≥ 70 且 quality ≥ 50；两者范围 0–100，默认可配置 |
| 排序 | 应用计算 `0.7 × relevance + 0.3 × quality`，再按发布日期降序、稳定文章 ID 排序；无日期排在同分有日期之后 |
| 入选上限 | 默认每批 10 篇；不为了凑数降低门槛，合格但超额者延后，下批复用结果 |

质量评分依据技术细节、证据、实现或实验、可复用性，不能仅按热度判定。每个评分附原文证据片段与理由；模型不决定实际文件路径和仓库权限。

### 内容不完整与长文章

- 正文缺失、验证页或明显付费摘要进入 pending，默认不生成“全文分析”；图示/附件未解析则在笔记中明确说明，不推断图中结论。
- 超过单次输入预算时按章节分块，默认每块最多 12,000 字符、重叠最多 500 字符，最多 8 块；逐块提取事实后再综合，保留片段来源。
- 超过总上限的内容标记 `content_too_large`，提供原文和失败原因，不静默截断后作为全文入选。用户可调整预算重试。
- JSON 结构或引用校验失败自动修复一次；仍失败则待处理。普通单次 AI 调用默认超时 120 秒，单篇含分块总预算 10 分钟。

## AI 工作区配置与运行

工作区预先保存 AIProfile：provider、CLI 绝对路径、模型、超时、任务策略；采集组引用或继承默认配置。首期同时实现 `codex_cli` 与 `gemini_cli` 两个适配器，同一任务只调用所选的一种。

- 首次设置完成 CLI 登录与最小非交互 JSON 测试，确认运行账户、PATH 和执行能力；任务中不弹出交互式确认。
- 认证过期、额度不足或不支持的版本返回可识别状态，在设置页处理后恢复，不以空摘要替代；不会自动切换到另一个计费方式。
- 每项任务使用独立工作目录和证据文件；子进程不接收 GitHub Token、Webhook 或仓库写权限。模型返回内容，应用负责渲染文件及同步。
- 记录 CLI 版本、实际模型、输入内容版本、提示词版本、耗时及可获得的 usage。CLI 未返回用量时标记 unknown，不假装为零。
- 普通处理仅使用提供的材料；不用网络搜索引入未经核实的新事实。全文、提示词与结果缓存保存在本地，按文章/组规则/执行器版本复用。

官方能力与精确调用方式见[本地服务与 AI 设计](../../design/local-service-and-ai.md)。本次只核查官方文档和本机 CLI 帮助，未代用户执行模型推理。

## 本地 AI 通过 skills 整理内容

03 的语义分类、导读、原文结构整理、调研和简报分别由版本固定的 skills 驱动。分类结果用于标签与阅读导航，不自动创建技术分类目录。

| Skill | 触发与输入 | 输出 |
| --- | --- | --- |
| `openlore-article-organizer` | 候选/入选文章分阶段运行；正文、组规则与图片清单 | 评估阶段返回分数与理由；整理阶段返回分类标签、标题建议、导读、原文与图注，对应 article.md |
| `openlore-article-research` | 勾选逐篇调研，或单篇手动触发；唯一主文章、调研要求及可读引用 | 该篇文章的机制解释、对照材料、适用条件、建议、证据与缺口；对应 research.md |
| `openlore-batch-digest` | 仅勾选简报时；本批已准备发布的文章卡片 | 批次概览与文章链接；对应批次根目录 digest.md |

运行器明确加载选定 Skill 的 SKILL.md、模板和白名单引用，记录版本与摘要值，不依赖 AI 临时决定是否触发。Codex/Gemini 适配器可以原生显式调用；本期自动化默认由运行器装载受控 skill 内容进入任务指令，两者使用同一输出契约。具体机制见[skills 与资源设计](../../design/content-skills-and-assets.md)。

Skill 可以整理文字、判断主题和提出文件标题；应用负责固定编号/路径、下载图片、校验引用和写入仓库。整理原文时保留作者观点与技术内容，AI 导读和补充推断必须明确分区，不能混入原文。

## 图片随文章完整归档

- 提取正文内的 img、picture/srcset、懒加载图片、Markdown 图片、data URI 和内联 SVG；选择原图或清晰版本，去除同一图片的响应式重复项。
- 配图、技术图表、图注相关图片都属于文章内容；导航图标、追踪像素等页面装饰不算文章配图。不能因为超过数量上限就静默漏图。
- 图片保存在该文章 assets/；article.md 和 research.md 均使用 `assets/文件名`。调研实际引用的新图片也归同一 assets/，保留出处与图注。
- 字节相同的图片在文章内复用；文件名包含内容 hash，防止覆盖不同图片。正文图片缺失时该篇 pending_assets，其他完整文章可继续发布。
- 默认每张图片最多 20 MiB、每篇资源合计 100 MiB；超过预算明确报告并允许调整，不当作成功下载。原图获取失败可尝试页面实际展示的版本，必须记录降级，不能用伪图片替代。
- 下载图片不等于理解图片；只有实际使用视觉能力读取后才允许引用图中结论。SVG 的脚本/外部执行内容需清理，不能执行页面代码。

## 逐篇深度调研与可选简报

开启组规则中的“逐篇深度调研”后，每篇入选文章分别创建任务；一项任务必须且只能绑定一个主 article_id。可读取这篇文章引用的补充材料，但不把几篇入选文章合并成一个研究任务。手动入口也只接受单篇；批量选择会拆成多个独立任务。

| 项目 | 明确策略 |
| --- | --- |
| 开关 | 默认关闭；开启后处理每篇入选文章，不再只选择 Top1 |
| 调研要求 | 组级默认要求应用到每篇；手动任务可覆盖。默认解释核心机制、验证论据、比较取舍并说明适用范围 |
| 模式 | `local` 只分析该篇已取得的材料；默认 `linked_web` 最多扩展 6 个实际引用页、深度 1 |
| 预算 | 每篇最多 3 次 AI 调用、任务总时限 15 分钟；全局 AI 并发默认 1，超出当日可用额度的任务排队，不静默跳过 |
| 产物 | 在原文章目录生成/更新 research.md；正文与研究互相链接，引用清单写在报告末尾 |
| 失败 | 有证据但材料不足时可产出明确标注的部分研究；图片未归档则暂缓发布研究。失败显示状态，不伪造结论 |

文章和已完成图片可以先发布，不等待调研；研究稍后完成后追加到原目录并更新导航，不再创建独立 research 分类文件夹或新的采集批次。每篇当前 research.md 代表最新研究，旧版本由 Git 历史保留；输入修订与 skill 版本控制复用，关闭开关不删除历史研究。

简报用于概览**本批多篇文章**，不承担逐篇深入分析。未勾选时不生成 digest.md；简单的批次 README 导航始终存在且由程序生成，无需额外 AI。简报调用最多一次加一次结构修复，预算 120 秒/次；失败不阻塞文章发布，可稍后补齐。

普通批次发布后，研究或简报补齐只更新同一批次目录内关联文件。超时和失败均恢复原任务，不重新执行已成功的文章整理。

## 输入输出与文件冻结

输入：组配置快照、文章版本与证据、AIProfile、skill 修订、产物开关与处理预算；输出：逐条 selected/excluded/pending/deferred 及原因、知识条目、研究报告、文件包和错误。详细字段见[处理与同步接口](../../design/processing-and-delivery.md)。

相同输入的成功结果复用；需要更新处理时创建新业务运行，不能把重试当成重新生成。任何 GitHub/消息重试只重用冻结的 batch_id、路径和文件内容。

## 验收

用固定样本验证 any/all/semantic、排除词、多来源归属和 70/50 门槛；实际分别验证一次 Codex 和 Gemini 的非交互 JSON 处理。对同一文章在两个组产生不同笔记；验证两个产物开关的四种组合、每项研究只有一个主文章、所有 Markdown 图片均为存在的本地 assets 文件；调研与简报均可独立补齐、重试与更新。
