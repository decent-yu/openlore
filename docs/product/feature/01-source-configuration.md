# 来源、工作区连接与采集组

## 产品目标

先配置可复用的仓库连接、通知连接和本地 AI，再建立采集组。管理员维护“有哪些来源、如何读取”；用户按组决定“关注什么、放到哪里”。首期是本机单用户服务，使用者同时拥有管理权限，不引入团队账户体系。

## 一次性设置：工作区连接

入口：设置 → 连接。连接保存后可被多个组引用，组内不重复填写 Token 或仓库地址。

| 连接 | 配置项 | 保存与启用检查 |
| --- | --- | --- |
| GitHub 仓库 | 名称、仓库地址、GitHub Token、默认分支 | 解析 owner/repo；验证 Token 可读目标仓库及内容写权限，读取实际默认分支；展示连接状态 |
| 消息通知 | 名称、Webhook 地址；首期协议固定为通用 JSON HTTP POST | 校验 URL；用户点击“发送测试消息”验证，失败显示原因；可不配置通知 |
| AI 执行器 | 名称、Codex CLI 或 Gemini CLI、可执行文件绝对路径、使用的模型 | 检查版本、非交互参数，用户执行一次最小 JSON 测试；模型留空时使用 CLI 当前默认模型并记录实际结果 |

- 可预配置多个仓库；选择一个工作区默认仓库和默认 AI。优先建议 Codex CLI，Gemini CLI 同样可选；备用执行器默认不自动切换。
- 仓库 Token 与 Webhook 单独保存；界面只回显脱敏信息。AI 沿用同一操作系统用户已经登录的 CLI，不复制登录凭据到 OpenLore 配置。
- 修改连接产生新修订；运行保存连接配置快照。撤销或停用凭据立即阻止后续调用，不能因旧快照继续使用已撤销授权。
- 检查不等于绕过分支保护；实际写入被拒绝时明确报错。空仓库在设置阶段提示先初始化，避免运行到同步阶段才发现。
- 缺少仓库或 AI 时，仍可预览来源；组只可保存草稿，不能启动完整处理。通知为空不影响仓库归档。

## 模块一：信息源管理

入口：来源 → 新增 / 编辑 / 预览 / 启用 / 停用。

| 内容 | 字段与规则 |
| --- | --- |
| 来源说明 | 名称、网站地址、主要内容、适合主题、内容特点与局限；选择前即可查看 |
| 采集入口 | 采集类型、Feed 或文章 URL、需要时绑定来源凭据；类型映射到独立能力适配器 |
| 运行策略 | 启用状态、轮询间隔；默认 30 分钟；限制单次网络请求和来源扫描预算 |
| 预览结果 | 返回格式、样例标题、正文/摘要状态、最近错误；预览不触发 AI、GitHub 或消息同步 |

来源说明中的主题只是帮助选择的标签，用户的实际筛选条件在采集组中维护。已启用且被启用组引用的来源才参与自动轮询；停用后保留历史内容，并在相关组中显示“来源已停用”。

| 首期来源 | 主要内容 | 选择提示 |
| --- | --- | --- |
| [Cloudflare Blog](https://blog.cloudflare.com/) | 网络、安全、数据库、性能优化、云基础设施及 Agent 工程实践 | 一手工程分析；筛选时降低纯产品发布与公司动态的优先级 |
| [Simon Willison](https://simonwillison.net/) | LLM 工具、编程 Agent、开发方法、实验与技术评论 | 原创长文、短评、外链推荐混合；短评不等于被推荐文章全文 |

入口与核查依据见[网站清单](../research/03-minimal-prototype/02-web-source-catalog.md)。

## 模块二：采集组与路由

入口：采集组 → 新建。用户按“基本信息 → 来源与筛选 → 归档路由 → 产物选项与运行计划”完成配置，可保存草稿、预览计划、启用、暂停、立即运行。

| 配置 | 首期规则 / 默认值 |
| --- | --- |
| 组名称、关注描述 | 必填，如“Agent 相关知识”；描述希望解决的问题或阅读方向 |
| 组内来源 | 至少一个已启用来源；每个来源可配置不同关键词与排除词 |
| 匹配模式 | `semantic` 默认，关键词作为语义提示；可选 `any` 或 `all` 严格关键词模式，定义见 03 |
| 内容偏好 | 默认优先实现细节、代码、实验数据、技术取舍；降低纯公告优先级 |
| 仓库连接 | 选择已保存连接，默认工作区默认仓库；不再填写仓库地址或 Token |
| 归档路由 | 必填仓库目录，如 `/docs/agent-leaning`；它是仓库内路径，不是本机目录 |
| 通知连接 | 选择已保存 Webhook，默认关闭；不改变仓库目标 |
| AI 执行器 | 默认继承工作区 AI；可为组选择已验证的其他配置 |
| 运行计划 | 默认每天 09:00，工作区时区默认 Asia/Shanghai；可改为固定间隔，或仅手动 |
| 内容数量 | 每批最多评估 20 篇，最多入选 10 篇；均可调整；首次只处理近 7 天 |
| 生成批次简报 | 复选框，默认关闭；勾选后为每个有效批次生成 digest.md |
| 逐篇深度调研 | 复选框，默认关闭；勾选后对每篇入选文章分别排队生成 research.md，可设置逐篇调研要求 |
| 内容整理 Skill | 默认绑定内置文章整理 skill；调研、简报 skill 按复选框启用，使用工作区已验证版本 |
| 图片归档 | 正文与调研使用的配图全部保存到该文章 assets/，Markdown 引用本地相对路径 |

所有默认值是本方案的初始产品策略，可在设置中调整，不是外部平台限制。排除词优先于正向关键词。正向关键词可为空，此时按组关注描述判断；空正向列表不作为 any/all 的拒绝条件。

## 一个完整配置示例

```text
工作区连接
  仓库：团队知识库 → github.com/example/team-knowledge（Token 已保存）
  AI：本机 Codex → 已登录且非交互测试通过
  通知：技术群 → Webhook 已保存

采集组：Agent 相关知识
  来源：Simon Willison（agent, tool calling）
        Cloudflare Blog（agents, MCP, Workers）
  匹配：semantic；关注 Agent 的工程实现与可靠性
  路由：团队知识库 → /docs/agent-leaning
  通知：技术群；AI：继承默认；每天 09:00；最多入选 10 篇
  产物：☑ 批次简报  ☑ 逐篇深度调研；图片随文章归档

采集组：后端性能优化
  来源：Cloudflare Blog（database, latency, performance）
  路由：团队知识库 → /docs/backend-performance
  通知：关闭；AI：继承默认；产物：☐ 批次简报  ☐ 逐篇深度调研
```

实际配置形态见[无秘密的配置样例](examples/workspace-config.json)。样例不是运行实例。

## 配置变化与运行边界

- 简报和逐篇调研的选择在运行开始时固定；修改只影响新批次，不删除已有产物。调研关闭时也可从单篇文章显式发起一次调研。
- 同一来源可加入多个组；组内筛选、路由、调研与交付互不影响，共享原始采集结果。
- 新来源加入组时执行该组首次回看窗口；改关键词或关注描述后，下次重新评估待处理条目与近 7 天已排除条目；已归档内容不会被自动删除。
- 改路由对新批次生效，不自动迁移历史；“同步历史到新路由”是显式操作，执行前展示目标与文件数量，按同一同步规则写入。
- 运行中的组配置固定；用户修改配置不会改变既有批次的目标。暂停组停止新调度，已生成文件包保留，可取消未完成交付。
- 同一仓库分支上的两个组不允许使用相同或相互包含的路由；路径冲突在保存时指出。
- 页面清楚区分“连接未就绪、草稿、启用、暂停”，并展示下一次运行时间与积压量。

## 验收

只配置一次仓库和 Token，即可创建两个不同路由的组；配置保存前能发现缺失连接、非法路由和路径冲突。组可独立运行、暂停与修改，用户始终能看到来源内容定位和实际同步去向。
