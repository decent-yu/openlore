# 来源配置

让用户清楚每个信息源提供什么内容，再配置关注主题、采集入口和范围。

## 首期信息源

| 信息源 | 主要内容 | 选用理由与筛选重点 |
| --- | --- | --- |
| [Cloudflare Blog](https://blog.cloudflare.com/) | 网络与安全、数据库、性能优化、云基础设施，以及 Agent 工程实践 | 获取一手工程分析；优先技术原理、实现细节与故障复盘，降低纯产品公告的优先级 |
| [Simon Willison](https://simonwillison.net/) | LLM 工具、编程 Agent、开发方法、实际实验与技术评论 | 补充 Agent 实践视角；优先原创分析和可复用经验，区分长文、短评与外链推荐 |

两者均通过订阅源发现内容，必要时补抓原文。网站采集入口、验证记录和后续候选统一维护在[网站信息源清单](../research/03-minimal-prototype/02-web-source-catalog.md)。

## 来源说明与配置

- **来源说明**：名称、网站地址、主要内容、适合关注的主题、内容特点与局限。用户选择前应能判断是否符合阅读需要。
- **采集配置**：启用状态、采集类型、订阅地址或文章 URL、关联主题与处理范围。首期支持 RSS/Atom 和单篇 URL。
- **主题配置**：主题名称、关注描述与筛选偏好；一个来源可以关联多个主题。

信息源是“从哪里获取”，采集类型是“怎样获取”，主题是“想看什么”。正文与主题的实际匹配由内容处理环节判断。

## 首期关注主题

- **Agent 工程**：工具调用、上下文管理、评估、可靠性、编程 Agent。
- **深度工程实践**：架构设计、性能优化、故障分析、数据库与基础设施。

优先选择有实现细节、代码、实验数据或明确技术取舍的内容。

## 预期结果

用户可根据来源说明选择信息源；修改主题或来源配置后，后续运行按新配置采集与筛选，无需修改采集代码。
