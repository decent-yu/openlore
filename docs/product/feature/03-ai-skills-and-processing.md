# 03 Skills 与 Prompt 调用流程

AI 由云端编排，独立 Runner 执行。部署见[系统架构](../../architecture/system-architecture.md)，接入见[Runner 指引](../../guides/ai-executors.md)。

## 内容池初审

新文章成功入池或正文版本变化后自动排队，使用主 AI 执行器及其备用执行器，调用 `tech-article-extractor`（extraction 类型）。不带流水线定位，读取全文，输出内容质量分、定位、简介、标签、评分理由和可核验的原文证据。

初审调度按主执行器配置的并发数领取任务，同一文章版本不重复在途执行；一个慢初审不占满其他可用槽位。本机/SSH 的审核、调研和备用接管共用该执行器的并发限制，Worker 使用服务端租约队列限制。等待槽位与实际 CLI 执行分别记录，排队上限和统一的执行时限分别生效。

结果按文章、正文版本保存在 `article_reviews`，各流水线共享。采集不等待 AI 完成，初审失败不回滚入池。缺少执行器或 Skill 时明确失败，配置修复后手动重试。服务重启后继续已排队任务，在途初审标为失败并允许手动重试。

仅含标题、日期或明确的页尾导航列表时标记为“材料不足”，不调用 AI、不生成质量分，也不自动反复排队；补充正文版本后重新初审。材料文件明确区分元信息和唯一可引用的正文区域，页尾导航不作为评分证据。

已有历史文章不会因升级、新建任务或运行流水线而自动补审。内容池提供单篇、本页未审核文章的手动审核，以及失败重试、重新初审；接口 `POST /library/review` 接收 `article_ids` 和可选的 `force`。

## 流水线任务

1. **AI 批量选文**：`selection_skill_id` 默认 `article-selector`（selection 类型）。输入候选的 ID、标题、共享质量分、定位、标签和简介；根据任务定位、`preferences` 和调研要求选择最多 M 篇，输出 ID 和理由，不生成任务评分。
2. **深度调研**：`research_skill_id` 默认 `deep-research-expert`（research 类型）。只对选中文章读取全文，按 `research_instructions` 生成研报。
3. **GitHub 归档**：文章与研报归档成功才计为完成，不调用简报 Skill。

候选过多时分批初选再合选，完整输入、输出与失败保留在每次选文调用中。初审结构或引用不合格时，携带原始结果、失败字段与原因，在同一执行器会话和工作区内纠正一次；不重新创建独立初审 Job。没有可续用会话或纠正后仍不合格时明确失败，不自动从头重跑、不保存无效评分。

首次执行、校验修正和备用接管归入同一条调用记录，展示全部尝试、累计耗时与已记录的 Token；缺失用量不填零，缓存计入累计用量但不直接作为费用。每次 CLI 执行仍沿用执行器配置时限，默认 900 秒；整条任务可能包含多次执行。

前后端共用 `packages/contracts/src/prompts.ts`。流水线编辑器分阶段选择选文和调研 Skill，可修改要求并预览完整 Prompt。初审独立于任务，不再在任务内配置审核 Skill。

## 文章表达与阅读

初审导读、简介、评分与选文理由，以及深度调研文章，默认面向有基本技术常识、但未研究过该领域的读者：先说明具体问题和做法，必要术语首次出现时就地解释。证据原句与技术标签保留准确内容，不为中文表达而改写引用。

研报默认按“问题 → 具体例子 → 工作原理 → 取舍 → 建议”由浅入深展开，按主题调整；源码、公式等进阶细节放在后面。篇幅、对比方案、排障步骤和 SVG 配图按需要决定，没有统一字数或配图数量下限。假设例子明确标注，保留事实出处、适用条件、代价和未知项，不编造效果数字。

归档时另外生成 `article-zh-CN.md`，翻译 Prompt 也统一放在 `prompts.ts`。译文使用自然、直白的中文，在原有文本节点内调整语序和句子表达，忠实保留原意与限制；不额外补定义、背景或例子，不套用研报模板。已有中文、文档结构、图片、代码等按[归档规则](05-git-delivery-and-archive.md)保留，不能为了易读改写原文。译文缓存同时匹配原文与完整翻译 Prompt，表达规则更新后会重新翻译。

汇报直接使用初审的 `positioning` 作为简短导读，不额外调用 AI。以上规则对新生成的内容生效；历史简介需手动重新初审，历史研报需手动重新调研。已有归档不会因升级自动重写。未归档研报只有在全文材料、完整提示词、Skill 版本与执行配置匹配时才复用。

表达要求同时写入共享 Prompt 和仓库 `skills/`。执行器读取自己的 Skills 目录时，共享 Prompt 仍携带读者与可读性要求；本机 Skill 及其参考文件的更新和目录刷新方式见 [Runner 指引](../../guides/ai-executors.md#skills-与首次业务验证)。[阅读对照样例](examples/plain-language.md)仅用于人工评审表达，不代表真实 AI 验收。

## 汇报与 Skill 来源

汇报方案读取归档结果，按模板生成并发送，不调用 AI。

同步模式从仓库 `skills/` 与业务数据目录 `skills/` 发现 Skill 并复制到执行工作区；本地目录模式使用执行器上报的目录和清单。Skill 不全局安装。执行器需同时提供初审、选文和调研所需 Skill。
