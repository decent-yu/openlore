# 02 流水线任务

入口 `/pipelines`。任务按 Agent 工程、前端学习等主题组织，消费内容池中的已有文章；采集周期和入池关键词在来源页配置。

## 任务配置

- 名称、主题定位、AI 审核要求、独立 Cron 和时区、启用状态。
- 池内来源范围：可选来源，不选表示整个内容池；只约束选文范围，不触发采集。
- 选文参数：精选篇数（默认 10）、从精选中调研篇数（默认 3）。时间窗仅在来源采集准入配置，任务不再设置。
- AI 执行器；审核阶段独立的 Skill 与附加 Prompt；调研阶段独立的 Skill 与附加 Prompt。编辑器可查看每阶段实际组合后的 Prompt。
- GitHub 仓库连接与归档目录。

任务不配置群通知通道。可以在汇报推送页将本任务与其他任务的结果合并汇报。

## 执行顺序

1. 从指定来源范围内读取内容池文章，只排除已精选或已成功深度调研的文章（跨任务去重），其余全部参与评估。按任务定位和审核要求评分，择优精选。
2. 审核阶段确定精选名单和其中的调研名单；调研阶段只接收确定的文章，逐篇生成独立的新文章。
3. 将文章、调研报告和图片一起归档到 GitHub。归档成功后，任务才标记完成。

运行阶段为 `processing → research → delivery → completed`；关闭调研时跳过 research。失败会保留所在阶段和错误，不能被汇报当作成功结果。审核与调研的 AI 调用失败时不会用固定模板伪装成功。归档前失败不会永久占用这些文章的精选资格，可以重新运行。

每次成功任务在 `runs.output_json` 保存文章标识、导读、归档链接、调研状态等结果。汇报只读取这些运行结果，不重新采集或重新执行任务。

## 存储与调度

任务服务沿用内部 `Group` 存储模型，公开路由为 `/api/v1/pipelines`。池内范围存于 `group_sources`。

来源轮询、任务执行与汇报发送独立调度，慢速采集不阻塞其他任务的定时检查。

## Skills 顺序

审核阶段只调用 `assessment_skill_id`，结合任务定位及 `preferences` 评估候选，并确定精选与调研名单；调研阶段只调用 `research_skill_id` 并应用 `research_instructions`，不重新选文。简报不属于任务阶段，只由汇报方案生成。

## 审核证据与复用

精选要求相关度至少 75、工程质量至少 70，必须提供可在正文中找到的引用证据。材料包含首发日期、来源、正文完整度和内容类型；长文按章节与文末取样，不只取开头。合格数量不足时少选。

相同文章材料、任务要求及执行器配置复用审核缓存；排除与待选决定也持久化。AI 失败或证据无法核验时明确失败，不生成固定评分。

执行器支持服务端本机、常驻 Worker 与 SSH。实际任务指令使用 `$skill-name`，Skill 包在每次任务的独立工作区同步，无需全局安装。详见 [AI Runner 协议](../../architecture/local-ai-executors.md)。

## 运行计数

扫描文章 = 来源范围内文章数；参与评估 = 扫描文章 − 已精选或已深度调研文章。按文章 ID 去重，多个来源不会重复计算。精选配额只限制最终输出，不限制参与评估数量。

流水线不检查发布时间、年份、采集状态、关键词或正文完整度。入池即代表准入完成。正文文件缺失属于存储错误，任务明确报错，不静默跳过文章。首页待评估数量与任务共用同一候选查询。
