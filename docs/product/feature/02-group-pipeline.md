# 02 流水线任务

入口 `/pipelines`。任务按主题配置来源范围、选文要求、调研要求、执行计划、AI 执行器与 GitHub 归档路径。

## 任务配置

- 首行配置任务名称、Cron 和执行器；默认时区为 `Asia/Shanghai`。
- 关注领域与定位供 AI 比较候选；来源范围留空表示全部来源。
- 选文使用 `selection_skill_id`（默认 `article-selector`）；深度调研使用 `research_skill_id`。
- 每次最多调研篇数 M 为 0–100。M 为 0 时不调用选文或调研 AI，内容池初审独立运行。
- 各阶段可编辑选文或调研要求并预览完整 Prompt；留空使用默认要求。

## 选文规则

**已初审内容池 → AI 批量比较评分、定位与简介 → 最多 M 篇 → 全文调研 → 成功归档。**

- 读取来源范围内所有已完成当前正文版本初审、尚未成功归档且未被占用的文章；不限制入池日期。
- 未初审、排队中、初审中及失败的文章跳过并统计；流水线不会补跑初审。历史文章在内容池手动审核。
- 初审质量分与任务方向无关。选文 AI 结合任务定位、选文要求和调研要求比较候选，不重新逐篇评分，不按固定权重算任务总分。
- 返回文章 ID 和选择理由；允许少选或不选。未知 ID、重复 ID、缺少理由或超过 M 均明确失败，不静默截断或替换。
- 通常一次比较全部候选。资料超过单次预算时，分批初选后对入围者合选；所有调用均记录。若无法缩减到可合选规模，明确提示减少 M 或缩小来源范围，不丢弃候选冒充全量比较。
- 未选中的文章下次仍可参与；新建任务直接复用共享初审，不触发历史文章重新审核。

## 调研、去重与重试

一次运行阶段为 `processing → research → delivery → completed`。来源采集独立运行，流水线只读取已入池文章。

选择调研文章时原子领取文章级占用，覆盖生成和归档全过程。不同流水线不能同时自动调研同一篇文章；已成功归档的文章默认跨流水线跳过。人工重新调研可以生成新版本，但同样不能与在途任务冲突。

研报生成成功不等于完成。`research_tasks.archived_at` 仅在 GitHub 确认交付成功后写入，首页和汇报只展示已归档研报。失败后释放占用，文章仍可进入后续运行；若相同材料和执行配置已有完整、未归档的研报，则复用它重试归档，不重复调用调研 AI。

服务重启会中断运行并清理在途占用；共享初审结果和完整待归档研报保留，手动重跑可继续复用。当前不承诺整个业务协程跨重启自动续跑。

## 运行记录

记录扫描数、已归档/在途跳过数、未初审跳过数、备选数、本次调研数及留待后续数。选文和调研调用关联本次 `run_id`，完整候选资料、入选 ID 与理由在 AI 调用日志查看。

`group_items` 保存选中文章与理由，不再保存任务评分。完成状态以已归档研报为准。实际执行协议见 [AI Runner](../../architecture/local-ai-executors.md)。
