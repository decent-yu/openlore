# 04 每日精选与内容池

首页 `/` 展示指定流水线成功归档的精选与调研成果；内容池 `/pool` 展示采集准入后的文章。两者不承担计划调度，也不依赖浏览器一直打开。

## 首页规则

- 选择流水线任务与日期；日期按工作区时区计算，以成功运行的完成日期归属结果。
- 审核、调研或归档未完成时显示运行状态；未成功归档的结果不作为完成精选展示。
- 精选数和调研数来自各流水线配置及实际合格结果，不固定为“10 篇、3+7”。数量不足时少选，无新增时不生成空归档。
- 已完成调研的文章展示研究结果，其他精选提供导读与原文入口；可手动发起深度调研、查看归档状态和链接。
- 爱心记录用户兴趣；主动调研也记录兴趣来源。当前不能据此宣称已经实现自动学习偏好或训练反馈闭环。
- 页面定期刷新任务状态，完整阶段和 AI 输入输出到“运行记录”查看。

## 内容池边界

入池前完成来源日期、正文与主题准入。待补全文、待复核或被拒收的采集候选不创建文章，不进入列表与统计；采集诊断在来源页查看。

筛选独立分为“发现时间”和“发布时间”两行：

- 发现时间：全部、今天发现、近三天发现、具体时间；按文章入池时间查询。
- 发布时间：全部、今天发布、近三天发布、具体时间；按文章首发时间查询，日期未知的文章不匹配已选发布时间范围。
- 具体时间使用开始/结束日期，包含起止两天；选同一天可查该日。日期按工作区时区计算，近三天为最近 72 小时。
- 两行时间、属性、来源、搜索和感兴趣条件取交集；修改筛选后从第一页显示。

属性互斥分为“暂未入选”“精选入围”“深度分析”：已有完成研报或深度分析标记的文章只归深度分析；已精选且未完成调研的文章归精选入围；其他池内文章归暂未入选，包括尚未审核、排除和待后续入选的文章。“感兴趣”独立开关，可以叠加任意属性。

计数按来源与搜索范围统计时间快捷项；属性计数按当前两行时间范围计算，三个状态计数之和等于该范围内文章数。列表按首发日期倒序。流水线消费来源范围内尚未精选/深度调研的池内文章，不再额外施加“近三天”窗口，详见[流水线规则](02-group-pipeline.md)。

## 接口与实现

| 接口                                          | 用途                                           |
| --------------------------------------------- | ---------------------------------------------- |
| `GET /api/v1/feed?group_id=…&date=YYYY-MM-DD` | 获取指定任务与日期的精选、研究、运行状态与计数 |
| `POST /api/v1/feed/research`                  | 对指定任务的文章发起深度调研                   |
| `POST /api/v1/articles/:id/interest`          | 修改文章兴趣标记                               |

响应字段以 `modules/feed/service.ts` 的 `DailyFeedResponse` 为准；当前池内计数字段为 `pool_count`，不再使用 `pool_count_last_3_days`。前端为 `features/feed/DailyFeedPage.tsx`，路由在 `http/routes/feed.ts`，内容池路由在 `http/routes/library.ts`。
