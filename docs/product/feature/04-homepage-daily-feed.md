# 04 每日研报与内容池

首页 `/` 只展示已完成并成功归档的深度研报；内容池 `/pool` 用于查看原文、评分、调研与归档状态。

## 首页规则

- 任务与日期可切换，日期按工作区时区的研报归档时间计算，不是原文发布时间或入池日期。
- 不展示未调研精选列表。生成中、失败或生成完成但待归档的文章不计入首页已完成结果。
- 当天多次运行的研报合并展示，不受单次 M 配额截断；同一文章展示该日最新已归档研报。
- 运行进度到“运行记录”查看，所有原文与评分到“内容池”查看。
- 首页和汇报都保留 Wiki 研报与正文入口；汇报只汇总当天成功归档的研报，不调用 AI。

## 内容池边界

入池前完成来源日期、正文与主题准入。待补全文、待复核或被拒收的采集候选不创建文章，不进入列表与统计；采集诊断在来源页查看。

筛选独立分为“发现时间”和“发布时间”两行：

- 发现时间：全部、今天发现、近三天发现、具体时间；按文章入池时间查询。
- 发布时间：全部、今天发布、近三天发布、具体时间；按文章首发时间查询，日期未知的文章不匹配已选发布时间范围。
- 具体时间使用开始/结束日期，包含起止两天；选同一天可查该日。日期按工作区时区计算，近三天为最近 72 小时。
- 两行时间、属性、来源、搜索和感兴趣条件取交集；修改筛选后从第一页显示。

属性互斥分为“未审核”“已评分”“深度分析”：未审核为没有有效评分；已评分为有有效评分但尚未成功归档研报；深度分析为有成功归档研报。取消精选入围和暂未入选分层。“感兴趣”独立开关，可叠加任意属性。调研中和待归档是执行提示，不冒充已完成。

文章卡片展示当前正文版本的共享初审结果：完成状态与质量分左右同排，摘要最多两行、标签最多一行，超出部分悬浮查看；待初审、排队和审核中使用紧凑状态提示，并与文章标题就近排列。点击“查看审核详情”打开弹窗，查看完整简介、评分依据、原文证据及时间，弹窗提供“查看初审记录”跳转。没有评分时不填零分；排队、执行中和失败状态单独展示。旧流水线相关度不能当成共享质量分。

新文章入池后自动初审；历史文章提供单篇初审和“审核本页未审核文章”，失败可重试，已成功初审可手动重新初审。初审使用主 AI 执行器和备用执行器，与流水线数量无关。正文版本变化后，旧评分不计入当前版本的已评分状态。

只有日期和导航、缺少可评估正文的材料显示“材料不足 · 未调用 AI”，属于未审核，不显示虚构分数或冒充执行失败。此状态不会自动重复初审，可在补充正文后使用“重新检查正文”。入池前识别出的同类候选保留在来源诊断中，不进入内容池。

计数按来源与搜索范围统计时间快捷项；属性计数按当前两行时间范围计算，三个状态计数之和等于该范围内文章数。列表按首发日期倒序。流水线消费来源范围内已初审且尚未完成调研的池内文章，不再额外施加“近三天”窗口，详见[流水线规则](02-group-pipeline.md)。

## 接口与实现

`GET /api/v1/feed` 返回指定任务/归档日期的研报、统计和运行状态；`deep_articles` 是唯一文章列表。`POST /api/v1/feed/research` 支持人工调研并归档，未建立归档目录的池内文章也可直接操作。`POST /api/v1/articles/:id/interest` 切换兴趣。

内容池接口为 `GET /api/v1/library`，属性参数为 `all / unreviewed / scored / deep`。筛选只影响阅读，不改变流水线候选范围。
