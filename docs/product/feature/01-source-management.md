# 01 来源采集

入口 `/sources`。来源独立发现候选、补抓原文并执行质量准入；只有通过准入时才创建内容池文章。

## GitHub 仓库研读

来源支持 RSS / Atom 与 GitHub 仓库。选择“GitHub 仓库”，填写仓库根地址（如 `https://github.com/stablyai/orca`），可指定分支 / Tag 和研读重点。读取默认分支时不假定分支名称。

新建“仓库研读”流水线并关联该来源，设置每天运行时间、AI 执行器、目标 GitHub 仓库和归档目录（如 `docs/xxx`）。GitHub 来源固定使用独立的 `github-code-research` Skill；“文章调研”流水线使用文章 Skill（默认 `deep-research-expert`），两类来源不绑定到同一流水线。未勾选来源表示使用全部同类型来源。运行时先确保当天的仓库材料已准备，再执行调研；采集按钮仅准备材料。每个仓库按系统时区每天准备一份材料，预览不消耗当天名额。仓库没有新提交或 Release 也能继续深入研读。

采集固定到一个 Commit，包含 README、目录以及轮换的源码采样，优先业务源码，每次最多 10 个请求。采样和目录截断会明确标记，不把采样当作整个仓库。API 限流或网络失败保留错误，不创建占位研报，也不推进当天进度。可匿名读取公开仓库，或选择已有 GitHub 仓库连接复用其凭据，提高读取额度并读取该凭据有权限的私有仓库。Token 仅由服务端读取，不发送到浏览器或 AI 执行器。

仓库研读不执行 RSS 的首发日期、关键词准入或文章初审，也不参与新闻选文；每轮在仓库材料队列中安排最多 M 篇研读，不占用文章调研任务的配额。调研会附带该仓库最近 40 篇已归档研报的标题与摘要，要求探索尚未充分覆盖的主题、追踪调用链、引用固定 Commit 的源码，并明确未验证的推断。历史上下文帮助减少重复，但不代表自动验证语义重复。

代码深研在 AI 启动前，由本地 / Worker / SSH 执行机检出固定 Commit 的完整跟踪源码至隔离目录 `input/repository/`，并写入 `input/repository.json`。采集片段仅作为线索，Skill 必须主动读取调用方、实现、测试和设计文档，以源码路径和行号支撑结论。只获取该 Commit，不拉取历史；子模块和 LFS 不自动下载，需要明确说明证据边界。源码准备时间计入执行器总超时。

执行机需要 Git 与 GitHub 网络访问。私有仓库需要执行机自身已配置的 Git 读取权限；来源连接中的 Token 只用于云端 API 采集，不传给执行机。源码准备或专用 Skill 缺失时失败，不回退到 `deep-research-expert`，不接受仅聊天回复代替 `output/research.md`。同步模式自动传送独立 Skill；本地 Skills 模式需要将 `skills/github-code-research` 安装到执行机配置目录并刷新目录。

研报第一行的主题标题用于命名。研报、源码材料与图片同批归档成功后，才在首页和汇报中展示。失败重试复用已生成的研报与原编号。目录结构见 [GitHub 交付归档](05-git-delivery-and-archive.md)。

## RSS / Atom 规则

- 默认每 30 分钟发现新条目；待补抓和未完成的 Feed 分页每轮调度继续处理。
- 默认采集今年内、最近 30 天首发的文章，首次同步同样遵守。超期内容直接拒收，不进入内容池。
- 默认从原文明确的发布日期元数据核验日期，区分首发、修改与发现时间；缺失、未来或冲突日期不直接进入可读池。
- 主题关键词支持词边界、常见概念变体。辅助模式允许 harness、模型路由、评测等明确工程主题补充命中，其他未命中内容留待复核；严格模式必须匹配关键词。
- 排除关键词和来源分类独立配置。默认排除 Company、Company Announcements、Global Affairs。
- 摘要与空内容补抓正文；失败记录原因，临时故障最多重试三次，HTTP 401/403/404 等直接标记失败，重评可重新尝试。

## 状态和同步

待补全文和待复核候选仅存在于后台采集队列，不创建文章、正文版本或内容池来源关联。通过准入后才进入 `articles` 和内容池。可用内容表示日期、正文和主题初筛通过。新文章成功入池后自动排队进行共享内容初审，采集不等待 AI 完成；初审失败仍保留池内正文与失败原因。

超期、规则拒收和最终失败候选丢弃正文与独立原始页面，只保留 30 天的诊断详情；到期仅保留身份、内容指纹和规则版本用于去重，避免反复抓取。规则改变允许重新发现。

来源卡展示准入、待处理、超期拒收、规则拒收和失败统计。保存规则只重评未入池候选，也可手动重评。文章入池后不再执行采集准入，不会因时间推移或配置变化被二次过滤。历史测试数据另行清理，不为其增加运行时豁免、迁移或保留分支。

每轮 Feed 最多发现 100 条，预览最多 10 条；剩余条目保存续读位置。发现候选先持久化，再保存 ETag；即使上游返回 304，也继续处理已排队候选。每来源每轮最多补抓 10 篇，有时间预算。补抓全文不能被后续 RSS 摘要降级覆盖。

`collection_candidates` 独立保存逐条状态、原因、重试及规则版本；`collection_runs` 保存采集配置快照与实现版本。`GET /sources/:id/quality-runs` 可查看最近运行，`POST /sources/:id/revalidate` 重评未入池候选。

Node 负责调度、规则和持久化，Python 负责 Feed 解析及正文提取。来源分类保留；URL 去掉 fragment 和追踪参数，保留语义查询参数。
