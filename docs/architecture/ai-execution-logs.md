# AI 执行时限与调用日志

系统设置 → AI 执行器 → 编辑：单次执行时限支持 10–3600 秒，默认 900 秒，界面以分钟编辑并提供 5/15/30/60 分钟快捷选择。已保存的显式配置不被默认值覆盖。保存仅影响新调用；每次调用记录启动时配置。

计时从 CLI 执行开始，到进程退出结束，覆盖模型生成及工具执行。达到上限终止本次进程，记录 timeout；主执行器失败后，备用执行器使用自己的时限。Worker 的排队等待上限独立配置，SSH 额外保留 20 秒传输开销。业务调用不再传递另一套未生效的 timeoutMs。

`ai_execution_logs` 保存每次实际调用，包括流水线审核和文章调研。当前汇报使用固定变量模板，不产生 AI 调用；已有简报调用仅是历史记录。命中审核缓存时不产生 AI 调用。调用开始即写入 running，按每次主备尝试更新；服务重启后未结束的调用标记 interrupted。

- 关联：调用 ID、job ID、run ID、任务、文章、阶段与 Skill 版本。
- 输入：实际 Prompt、传给 AI 的材料、输出 JSON Schema、实际加载的 SKILL.md 与引用文件列表。
- 输出：完整解析结果；不同执行器的返回分开保存。
- 每次尝试：执行器、模型、连接方式、开始结束时间、耗时、实际执行时限、Worker 排队上限、错误码和错误信息、CLI 退出码、stdout/stderr、可取得的 Token 用量。
- 超时：保留可安全读取的未完成文章文件，仅供核查；不当作成功结果自动发布。
- 脱敏：已知凭据、Bearer 和常见密钥字段在日志入库前替换；不记录执行环境变量。

`GET /api/v1/execution-logs` 支持 run_id、job_id、log_id 精确过滤，以及状态、阶段、文章/调用 ID/Skill 搜索与分页；列表不传完整输入输出。`GET /api/v1/execution-logs/:id` 按需返回完整详情，沿用管理 API 的认证。界面支持复制正文和导出脱敏 JSON。

“完整输入/输出”指应用实际传入和取得的文本，不是模型隐藏推理。原始 CLI 输出保留末尾最多 512KB，超出时明确显示截断；执行器未提供的 Token 数据显示未提供。历史任务的 ai_logs 仅有摘要，缺少的材料、时限和失败尝试不补造。

## 运行记录入口

运行记录固定为流水线任务、推送日志、AI 调用日志三个页签。流水线卡片内按 run_id 查询，有历史 AI 关联的推送记录按 ai_log_id 查询，跨任务入口提供全部调用；三处复用同一详情，不复制底层记录。历史汇报调用单独使用 report_plan_id，避免与流水线 group_id 混用。详情可返回所属运行或推送方案。完整产品与关联设计见 [运行记录与 AI 调用追踪](../product/feature/07-run-records.md)。

## 仓库研报复用

源码研读不按引用格式、行号或 Commit 验收。CLI 异常但留下有效研报时，记录实际退出码和诊断，调用结果按已接纳研报记为成功并附说明。日志记录输入的历史研报篇数，区分新会话、会话续用与复用已有产物。历史产物恢复追加 `recovery` 事件，原错误保留，不计为一次新的模型调用或 Token 消耗；运行批次的失败条目和部分归档结果分别保存。
